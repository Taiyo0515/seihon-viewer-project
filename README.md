# 製本ビューア(開発リポジトリ)

**このリポジトリは開発中です。** 配布用の zip の Release(GitHub Releases)はまだ付けていません。
試すための zip が必要なときは、下の「配布用の zip を作る」の方法で `src/` から作ってください。

製本表示(表紙は単独、2ページ目以降は見開き)に対応した PDF ビューアの Chrome 拡張機能「製本ビューア」の、
開発を引き継ぐためのリポジトリです。最新版は **0.7.0** です。

- 拡張機能の使い方(利用者向けの説明書)は **`src/README.md`** にあります。
- 開発の引き継ぎの資料は **`HANDOVER.md`** にあります(目的と現状・ファイルの役割・受け取った資料の扱い・設計方針・既知の課題・守る決まり)。
- このファイルは、このリポジトリの使い方です。

## 中身

```
seihon-viewer-project/
├── HANDOVER.md      引き継ぎ資料
├── README.md        このファイル(リポジトリの使い方)
├── .gitignore
├── .git/            git の履歴(0.1.0 から。タグ v0.3.0〜v0.6.3)
├── src/             拡張機能 0.6.3 の全ファイル(Chrome に読み込むフォルダ。manifest.json がある)
├── dist/            配布用の zip(seihon-viewer-0.6.3.zip。中身は src/ と同じ。git の管理の外なので、GitHub からは見えません)
├── examples/        会話の中で受け取った資料の原本(仕様書・指示書・旧版・画面・スキャン)
└── dev/             開発用の試験と道具(配布物には入れない)
```

## 拡張機能を使う(導入・更新)

- **新しく入れる**: `dev/make_dist.py` で作った zip を展開し、できた `seihon-viewer` フォルダを、ずっと置いておける場所に置きます。
  Chrome で `chrome://extensions` を開き、「デベロッパー モード」をオンにして、「パッケージ化されていない拡張機能を読み込む」でそのフォルダを選びます。
  詳しくは `src/README.md` の「3. 導入方法」を見てください。
  - `src/` フォルダをそのまま読み込むこともできますが、このリポジトリを動かしたり消したりすると拡張機能が動かなくなるので、
    展開した別の場所に置くほうが安心です。
- **新しい版に更新する**: 今の `seihon-viewer` フォルダの中身を、新しい版の中身ですべて置き換え、`chrome://extensions` で製本ビューアの「再読み込み」を押します。
  拡張機能の ID を固定しているので、設定・収集したページ・ページ役割はそのまま残ります(`src/README.md` の「4. 更新方法」)。
- 使い方の全体は `src/README.md` の 6章、詳細設定は 8章、動作の確かめ方は 12章です。

## 別の Claude(新しい会話)に開発を引き継ぐ

1. `HANDOVER.md` の **4章の「必ず添付」** のファイルを、新しい会話に添付します
   (`HANDOVER.md`・`dist/seihon-viewer-0.6.3.zip`・仕様書・国語と横置きのスキャン・傾いたページの画像)。
2. `HANDOVER.md` の **8章** の文を送ります。

## 配布用の zip を作る

`src/` を直したあと、配布用の zip(中は `seihon-viewer/` フォルダ)を作るには:

```sh
python3 dev/make_dist.py          # dist/seihon-viewer-<版>.zip(版は src/manifest.json の version)
```

同じ名前の zip があるときは上書きしません(置き換えるときは `--force`)。Python 3 の標準ライブラリだけで動きます。

## 開発用の試験を動かす(Linux)

```sh
sh dev/setup.sh      # 最初に1回(試験の PDF を dev/pdfs にそろえる)
sh dev/run-all.sh    # 全部の試験(145 項目)
```

必要な道具(Node.js・Playwright・Chromium・Xvfb・poppler-utils など)と、1つずつ流す方法は `dev/README.md` にあります。

## examples/ について

- 会話の中で受け取ったファイルの**原本**です(中身は変えていません。名前だけ、内容の分かる名前にしました)。
  受け取ったときの名前・用途・新しい会話で添付が必要かどうかは、`HANDOVER.md` の 3章にあります。
- 旧版の zip と、スキャン(`scans/`・`scan-images/`)は git では管理していません。個人の資料・市販の本のスキャンを含むので、**公開の場所には置かないでください。**

## git について

- 0.1.0 からの履歴とタグ(`v0.3.0`〜`v0.6.3`)がそのまま入っています: `git log --oneline --decorate`
- 拡張機能は `src/` へ移してあります。移す前の履歴は `git log --follow src/<ファイル>` でたどれます。
- `dist/`、`dev/pdfs/`・`dev/logs/`、`examples/` の大きなファイルは `.gitignore` で管理の外にしています。

## 大事な決まり(抜粋。全部は HANDOVER.md の 7章)

- 勝手に上書き保存しない(保存は常に新しいファイル)。
- 外部に何も送らない(解析・広告・更新確認なし。ライブラリは同梱)。
- 権限は必要最小限にし、`src/README.md` の 9章に理由を書く。
- 画面・説明・コメントは日本語。
