# 製本ビューア(Chrome 拡張機能)

製本表示(表紙は単独、2ページ目以降は見開き)に対応した PDF ビューアです。
PDF.js をもとに、Chrome 標準の PDF ビューアに近い見た目と操作で動きます。
ページを元の画質のまま画像や PDF にして貼り付けられる「コピー」、複数の PDF のページを溜めておける「ページ収集」、
中綴じの本を印刷するための「製本用PDF出力」、プリンターでスキャンした見開きを1ページずつに分けて余白を除いたり、
ばらした冊子を表紙から順に並べ替えたりする「スキャンの整え」もあります。
0.4 からは、電子書籍(EPUB・MOBI・AZW・AZW3)とコミック(CBZ・CBR)も表示でき、PDF への変換・PDF からの変換(画像・CBZ・EPUB・テキスト)もできます。
個人利用のための拡張機能で、Chrome ウェブストアには公開していません。

## 1. できること

### フェーズ1(表示)

- PDF を開くと、自動で製本ビューアに切り替わります(http / https / ローカルファイル)。
- **製本表示**: 表紙(1ページ目)は単独、2ページ目以降は見開き。左綴じ・右綴じを切り替えられます。
  通常の見開き・単ページにもワンタッチで切り替えられます。
- Chrome 標準ビューアとほぼ同じツールバー: サイドバー(サムネイル・しおり)、ページ番号、拡大縮小、
  ページ/幅に合わせる、回転、注釈(ペン・蛍光ペン・テキスト・消しゴム)、ダウンロード、印刷、その他メニュー。
- 検索(Ctrl+F)、テキストの選択とコピー、リンク、フォーム入力、パスワード付き PDF。
- 「**Chrome標準で開く**」ボタンで、同じ PDF をいつでも Chrome 標準ビューアで開けます(戻る手段もあります)。
- 「ファイルを開く」とドラッグ&ドロップ。
- ログインが必要なサイトの PDF も、そのサイトのログイン状態のまま開けます。
- 詳細設定画面、初回の案内画面、速度ログ。

### フェーズ2(コピー・ページ収集)

- **ビューア内の右クリックメニュー**(ページとサムネイル)。文字を選んでいるときは「選択した文字をコピー」も使えます。
- **コピー**(0.1 までの名前は「AI用コピー」): ページを右クリック →「コピー」(Ctrl+Shift+C)で、ページの画像がクリップボードに入り、
  チャット欄や文書にそのまま貼り付けられます。複数ページは1つの PDF(元の文字・図形のまま)にしてコピーします。
- **ページ収集**: 右クリック・サムネイルの複数選択・範囲指定(3-7、10)・PDF 全体でページを溜めておき、
  まとめて1つの PDF、または PNG(ZIP)で書き出せます。ブラウザを閉じても残り、複数の PDF をまたげます。
- **強制ダウンロード対策**(第1層・第2層・第3層): 「表示せずに保存させる」サイトの PDF もビューアで開きます。
  それでも保存されてしまった PDF は、保存されたファイルを自動でビューアで開きます。

### フェーズ3(ページ役割・製本用PDF出力)

- **ページ役割**: ページに「カバーの表紙・カバーの裏表紙・表紙・裏表紙・帯・表紙の折り返し・裏表紙の折り返し・しおり」の役割を付けられます
  (0.2 で名前を変え、3つ足しました。右クリック・専用パネル)。
  サムネイルに役割のバッジが出ます。PDF ごとに保存され、同じ PDF を開き直すと復元されます。
- **製本用PDF出力**: カバーの表紙(候補から選択)+ 本文 + カバーの裏表紙を並べ、4の倍数になるよう白紙を入れ、
  中綴じ用に面付け(用紙1枚の表裏に4ページ)した PDF を作ります。用紙は元のページから自動で選びます(A5 の本なら A4 横)。
  表紙・帯・折り返し・しおりなどの「付属」は別の PDF に出力します。元の文字・図形のまま作り、画像にはしません。

### フェーズ4(仕上げ)

- **設定の書き出し・読み込み**: 詳細設定とページ役割を JSON ファイルに書き出し、別のパソコンや入れ直した製本ビューアに読み込めます。
  読み込む前に、何が変わるかを確認できます。
- **付属の役割の使い道**: 表紙・裏表紙・帯・折り返し・しおりの役割のページを、製本用PDF出力で「付属として出力 / 最初のページの候補 /
  最後のページの候補 / 出力しない」のどれに使うかを、詳細設定と出力の画面で変えられます(運用が違う場合のため。0.1 までは帯の3つの役割だけ)。
- **保存しているページ役割の一覧**: 詳細設定で、役割を保存している PDF の一覧を確認し、消せます。
- **詳細設定画面の整理**: 仕様の第12章の全項目を、初期値どおりに並べ直し、上に目次を付けました。
- **注釈の仕上げ**: ペンで描いた線を1本ずつの注釈にしました(消しゴム・元に戻すが1本ずつ効きます)。消しゴムで消すときに
  画面の裏でエラーが出ることがあったのを直しました。
- **見開きのページ番号**: 見開きの右のページへ移動したとき(ページ番号の入力・サムネイル・しおり・リンク)、ツールバーの番号が
  移動した先のページを示すようにしました(以前は見開きの左のページの番号になっていました)。
- **速度の再計測**: 3種類の PDF で Chrome 標準ビューアと比べ直しました(下の「11. 速度比較の結果」)。

### 0.1(実機での確認を受けた修正と追加)

- **印刷の修正**: 印刷ボタンを押しても1ページ目(表紙)しか印刷されなかった不具合を直しました。全部のページが印刷されます。
  印刷の画質も選べるようにしました(初期値は「自動」: 50ページまでは 300dpi、それより多いときは 150dpi)。
- **「幅に合わせる」のずれの修正**:
  - 右綴じで拡大すると、左のページが画面の左外にはみ出し、横にスクロールしても見られなかったのを直しました。
  - ページの大きさがそろっていない PDF(スキャンした本など)では、「幅に合わせる」を押しても見開きが画面からはみ出し、
    横にずれて見えていたのを直しました。いちばん幅の広い見開きが収まる倍率にします。
  - 表紙の隣の空き枠の大きさが、隣のページと違うまま残ることがあったのを直しました。
  - サイドバーを開いたとき、中身が 8px 右にずれて枠からはみ出していたのを直しました。
- **右綴じの矢印キー**: 右綴じでは ← キーで次のページ、→ キーで前のページへ進みます(本をめくる向きと同じ)。
- **ページの選択と削除**(サイドバー): サムネイルの見出しの「**選択**」を押すと、各サムネイルの左上に丸が出ます。
  押すとチェックが付き、選んだページを**まとめて削除**したり、**役割(表紙・帯など)をまとめて付けたり**できます。
  サムネイルにマウスを置くと右上に ✕ が出て、押すとそのページを削除します。削除の直後は「元に戻す」で戻せます。
- **保存**: ページを削除したり書き込んだりすると、ツールバーに「**保存**」ボタンが出ます。押すと**保存先を選ぶ画面**が出て、
  新しい PDF として保存します(名前は `元の名前_編集済み.pdf`。元のファイルを勝手に上書きしません)。
- **閉じる前の確認**: 保存していない変更があるとき、⋮ →「**PDFを閉じる**」(新しく足しました)・別の PDF を開く・「Chrome標準で開く」を押すと
  「変更を保存しますか?」(保存する… / 保存しない / キャンセル)を出します。タブの × や Ctrl+W で閉じる・再読み込みするときは、
  Chrome の確認(「このサイトを離れますか?」)が出ます。
- **表紙・帯の指定を見つけやすく**: 製本用PDF出力の画面に「表紙・帯のページ」の欄を作り、表紙・裏表紙・帯表紙・帯裏表紙・帯を
  全部のページから選べるようにしました(選ぶとそのページの役割として保存されます)。⋮ メニューにも「ページを選ぶ(削除・表紙や帯の指定)」を足しました。
  (0.2 で役割の名前が変わりました。下の「0.2」を見てください)

### 0.2(追加のご依頼のフェーズ1: 画質・コピー・表示・役割)

- **最高画質**(初期値): 画像の保存・コピーと印刷に、「高画質」より上の「最高画質」を設けました。
  - **画像**: スキャンしたページは、元の画像と同じ解像度で画像にします(拡大も縮小もしない)。文字・図のページは 600dpi で描きます。
    ファイルに保存するときは、ページが1枚の JPEG 画像だけでできていれば(スキャンした PDF の多く)、**元の JPEG をそのまま**取り出します
    (作り直さないので、画質も大きさも元とまったく同じ)。詳細設定で「高画質(長辺 2400)」「標準(長辺 1600)」「指定する」にも変えられます。
  - **印刷**: 元の PDF のまま、Chrome の印刷機能で印刷します。画像は元の解像度、文字は文字のまま印刷され、印刷画面で「**PDF に保存**」を選ぶと、
    元の画質のまま、**OCR の文字**(スキャンした PDF の検索できる文字)も残った PDF になります。ページの削除や書き込みも反映します。
    0.1 までの「ページを画像にして印刷」(高画質 300dpi・標準 150dpi・自動)も選べます。
  - **PDF の保存・コピー**は、もともと元の画質のまま(画像を作り直さない)で、OCR の文字も残ります(0.2 で試験を加えて確かめました)。
- **「AI用コピー」を「コピー」に改名**しました(右クリックメニュー・⋮ メニュー・サイドバーの操作バー・詳細設定・ショートカットの説明)。
  文字を選んでいるときの通常のコピーは「選択した文字をコピー」という名前にしました。
- **「PDF としてコピー」「画像としてコピー」**: ページ収集のパネルに足しました(サムネイルを複数選んだときの右クリックにも)。
  押すと、裏で PDF・画像のファイルを作って保存し、**ファイルとしてクリップボードに入れます**。フォルダやチャット欄などに Ctrl+V で貼り付けられます。
  - ブラウザの決まりで、拡張機能だけではファイルをクリップボードに入れられないため、小さな**補助プログラム**(Windows・Mac・Linux 用。`helper` フォルダ)を
    入れると、この動きになります(入れ方は 6.14)。補助プログラムが無いときは、保存したファイルの場所(パス)を文字でクリップボードに入れます
    (ファイルを選ぶ画面の「ファイル名」の欄に貼り付けると、そのファイルを選べます)。
  - 「画像としてコピー」は、1ページなら画像そのもの(補助プログラムは不要)、複数ページなら1ページ1枚の画像ファイル(詳細設定で ZIP にもできます)。
  - 複数ページの「コピー」(サムネイルを選んで Ctrl+Shift+C など)も、初期値を「PDF としてコピー」にしました。
- **表示モードのボタン**: 押すと選択肢を出さずに**すぐ切り替わります**。押すたびに **単ページ → 製本表示 → 見開き → 単ページ** の順です。
  その**右に綴じ方向のボタン**(左綴じ ⇔ 右綴じ)を足しました。
- **「ページに合わせる」**: ページとページの間を見ているときに押しても、**いちばん大きく見えているページ**(見開きの表示では、その見開き)を、
  画面にちょうど収まる大きさで**画面の真ん中**に表示します(0.1 までは、中途半端な位置のまま大きさだけ変わっていました)。
- **ページ役割の名前の変更と追加**(製本用PDF出力):
  表紙 → **カバーの表紙**、裏表紙 → **カバーの裏表紙**、帯表紙 → **表紙**、帯裏表紙 → **裏表紙**。**帯**は製本用PDF出力の画面で**何ページでも選べます**。
  **表紙の折り返し・裏表紙の折り返し・しおり**を足しました。カバー以外の役割のページは「**付属**」として、本体とは別の PDF(`元名_付属.pdf`)にします。
  付けてあった役割は、新しい名前でそのまま引き継がれます(例: 0.1 で「表紙」を付けたページは「カバーの表紙」になります)。
- **元のリンク・ファイルの場所のコピー**: ツールバーのファイル名の右に、鎖のボタンを足しました。Web の PDF なら**リンク**(表示中のページへのリンクも)、
  パソコンの PDF なら**ファイルの場所・フォルダの場所・ファイル名**をコピーできます(6.13)。⋮ メニューからも開けます。

### 0.3(追加のご依頼のフェーズ2: スキャンの整え)

- **見開きの自動分割**: 本・ノートを開いてプリンター(コピー機)でスキャンした PDF を開くと、ノド(綴じ目の影・線)を見つけて、
  **1ページずつに分けて**表示します。分ける位置は紙の真ん中ではなく、見つけたノドの位置です(本を少しずらして置いても合います)。
  初期値は自動です(詳細設定で「分けるかどうか聞く」「何もしない」にもできます)。
- **余白の除去**: 手で置いてスキャンしたときに入るもの(本のまわりの余白・ふたの影・本の縁の線・ノドの影・ごみ・綴じ穴の影など)を除いて、
  中身(文字・図・書き込み)の周りに少し(6mm)余白を残して切り取ります。**全部のページを同じ大きさ**にそろえ、文字の位置もそろえるので、
  ページをめくっても文字の位置がずれません。
- **冊子の並べ替え**: ばらした中綴じの冊子を両面スキャンした PDF(2ページ分が並んだ平らな紙)では、ツールバーに「**冊子を並べ替える**」が出ます。
  押すと、真ん中で2つに分けて、**表紙 → 裏表紙の順**に並べ替えます(お送りいただいたサンプル3で、ページ番号を見て並びを確かめました)。
  スキャンした順(外側の紙から/内側の紙から)、裏面が上下逆か、綴じ方向も選び直せます(プレビュー付き)。
- **元の画質のまま**: 画像は作り直しません。元のページの「表示する範囲」を変えた新しいページを作るだけなので、画質は元のまま、
  ファイルの大きさもほとんど変わりません。OCR の文字は、それぞれのページに入る分だけを残します(検索・文字のコピーで、もう片方のページの文字を拾わない)。
- **整えた PDF の保存**: ツールバーのボタン(「分割表示」など)→「整えた PDF を保存…」(またはダウンロードボタン・Ctrl+S)で、
  保存先を選んで `元の名前_分割.pdf`(冊子は `元の名前_並べ替え.pdf`)として保存します。元の PDF のファイルは変えません。

### 0.8.1(傾いた縦長のスキャンを、開いたときに自動でまっすぐにする)

- **縦長のスキャン(1ページずつのスキャン)が傾いているとき、開いたときに自動でまっすぐにして表示します**(0.7 までは、ボタンと案内で知らせていました):

  中ほど(全体の約 40%・約 70% の位置)2ページも調べて判断するので、途中からずれた束をスキャンしたものでも見つけやすくなりました。

- 「スキャンした見開き」が「**聞く**」のときは、これまでどおりボタンと案内で知らせます。「**何もしない**」・傾きが「**既定では入れない**」のときは、開いたときには自動でしません

### 0.8.0(スキャンを整える: 設定の整理と部分表示)

- **「スキャンを整える」の画面を整理しました**: 選び方を「**ページの構成**」(**見開きを1ページずつに分割する / 冊子のページを読む順に並べ替える / ページの分割・並べ替えを行わない**)と「**補正**」(**余白を除く・傾きをまっすぐにする**。どの構成でも使えるチェック)と「**条件**」(本を読む向き・PDF の1ページ目・冊子のスキャンした順)に分けました。
  0.7 までの「傾きだけをまっすぐにする」「余白を除く」「元のまま」は、次のように読み替わります(選び方が違うだけで、整え方そのものは同じ):
  - 「傾きだけをまっすぐにする」→「ページの分割・並べ替えを行わない」+「補正: 傾きをまっすぐにする」
  - 「余白を除く」→「行わない」+「補正: 余白を除く」(傾きも組み合わせられます)
  - 「元のまま」→「行わない」+ 補正のチェックを両方外す
- **大きなスキャンでも、いまのページからすぐ表示します**(全部のページの解析を待たない):
  開くと、**いま見ているページのまわりを先に調べて**整えて表示し、残りのページは表示しながら裏で順に調べて、
  終わりしだい**全部のページで組み直して**静かに開き直します。

- **整え方を変えるとき、まわりの表示を活かします**: プレビューも、調べたページから順に表示が増えていきます
  (まだ調べていないページは「元のまま入る」として出ます。灰色の枠)。「この方法で表示」は、近いページが決まっていれば押せます。
  冊子の並べ替えだけは、全部のページを調べてからでないと並びが決まらないので待ちます(「この方法で表示」は、並びが決まってから押せます)。
- **そのほか**: 整えた PDF の保存名は、0.7 までと同じ(`_分割`・`_並べ替え`)+「行わない」で補正だけしたものは `_傾き補正`・`_余白` を付けます。

### 0.7.0(画質の統一: dpi を基本に)

- **画像にするときの画質設定を共通に、dpi を基本にしました**(コピー・画像の保存・ZIP・変換で同じ設定を使う):
  **元データ優先(初期値・今までの「最高画質」と同じ)/ 高画質 300dpi / 標準 150dpi / 指定する dpi(100〜1200)**。
  dpi は紙の 1 インチを何ピクセルで描くかで、ページの大きさからピクセル数が決まります(A4 は 300dpi = 2480×3508、150dpi = 1240×1754 ピクセル)。
- 「高画質・標準」の**値の意味が変わりました**: これまでの長辺 2400/1600 ピクセル → 300/150dpi(A4 ではほぼ同じ大きさ)。
  「指定する」に入れていた長辺ピクセル・倍率は、**dpi に換算して引き継ぎます**(倍率 1 = 96dpi。長辺ピクセルは A4 の長辺 297mm で換算)。
- **「元のままで動く部分は、画質設定の対象外」と言葉を整えました**(動きは変わっていません)。
  PDF の保存・コピーはいつも元の PDF の文字・図・画像のまま(OCR の文字も残る)。印刷は「**元の PDF で印刷**」(おすすめ。昔の「最高画質」)と
  「**画像として印刷**」(高清質 300dpi / 標準 150dpi / 自動)の分け方を明示しました。
- 変換(画像の ZIP・CBZ・EPUB)も同じ共通の入口から画像を作ります。変換の画面では、dpi と PNG/JPEG・元画像の使い方を回ごとに上書きできます(スキャンのページは元の解像度のまま)。

### 0.6.7(スキャンの整えの結果の保存)

- **一度整えた PDF は、次に開くとき調べ直しません**: 整えの結果を拡張機能の中(IndexedDB)に保存しておきます。
  保存しておくのは、**どのページのどこを切り出すか・傾き・並び順という「変更の内容」**(軽い)と、
  仕上がりの PDF(次回を速く開くため。元の PDF ごとにいちばん新しい整え方だけを残し、合計の大きさにも上限を付けます)。
- 開いた PDF は、**中身の指紋(ハッシュ)で前の計画と対応します**(ファイルの場所や名前が変わっても同じものは同じ)。
  ページ数が合わない・中身が壊れているときは、保存を捨てて、いつものように調べ直します。
- 効果: 傾きのスキャン・見開きのスキャンなど、**2回目以降の表示が数秒台に**(1回目と同じだけかかる「全ページの解析」と「組み直し」を飛ばします)。
  分け方を変えた整え方にするときは、その整え方の保存が無いので1回だけあらためて調べます。
- 元の PDF が変わりうる(見ている文書のページを削除するなど)場合は、中身の指紋が変わるので保存を使いません。

### 0.6.6(読み込み中の進捗の表示)

### 0.6.5(分けないページの余白の除去: 写真のページの余白)

- **紙が余白の中に写っているページの余白の除去**: 写真など、紙(はがき・カード・本など)が背景(余白)の中に小さく写っているページでは、
  これまで「余白を除く」が効きませんでした。新しい「**余白を除く**」の整え方(スキャンを整えるダイアログ)で、紙のまわりの余白を切り取ります。
  紙の範囲は、背景の明るさとの違い(白い背景の上にわずかに暗く写る紙の面・端・落ち影)から見つけます。
  背景が暗い(机の上に置いて撮った写真など)ときは、背景より明るい所を紙として探します。
  見つけた範囲は、紙の端の線まで締めます(端のすきとおった影を含んで拾うことがあるため)。切り取りは紙の端ぴったりです。
- 開いたとき、このようなページの PDF では(詳細設定が「自動」のとき)自動で余白を除いて表示します
  (「分けるかどうか聞く」のときは、ツールバーに「余白を除く」のボタンが出ます)。
- 紙の範囲が分からないときは、何も変えません。スキャンした文書のページ(白い紙に印刷したもの)は、紙の箱の外にまだ本文が残るので
  「背景の中に写った紙」とはみなさず、余白を除きません。傾きの補正と組み合わせられます(0.6 と同じ)。
- 見開きと分けられないページが混ざっているときは、分けられないページも同じ「余白を除く」の判断で余白を除きます(0.6.5)。

### 0.6.0(追加のご依頼: 傾いたスキャンをまっすぐにする)

- **傾き補正**: スキャンのとき、紙が少し傾いて入ると、文字の行が斜めになります。ページごとに傾き(約 0.2° 〜 8°)を調べて、まっすぐに直します。

  - **縦長のスキャン**(1ページずつのスキャン)が傾いていると、開いたときにツールバーに「**傾きを直す**」のボタンと知らせが出ます。

  - 「スキャンを整える」の画面に「**傾きだけをまっすぐにする**」を加えました(分けず・並べ替えず、傾きだけ直す)。

  - 詳細設定の「スキャン・ページ操作」→「スキャンの整え」→「傾き」で、「傾きを見つけたら、まっすぐにする」(初期値)/「自動では直さない」を選べます。
  - 保存: 整えた PDF の保存(`元の名前_傾き補正.pdf`)も、画像を作り直さず、元のファイルは変えません。
- **できないこと**: ページの中でも場所によって傾きが違う(本のページが波打っている)ものは、ページ全体の傾きだけを直します。
  ノドの影が文字の下まで続く部分は、0.5.0 と同じく残ります。

  一番下の「**既定の設定を上書きする**」をオンにして回転すると、回転ボタンを押したときの動きがその向き・角度になります(詳細設定の「開く・読む」→「表示」→「回転ボタン」でも変えられます)。
- **製本用PDF出力の画面**
  - ダークモードで、ページを選ぶ欄(ドロップダウン)の一覧が白地に白い文字になって読めなかったのを直しました(ビューア・詳細設定・電子書籍リーダーのすべての選択欄)。
  - 出力ページのプレビューは、初めから「**表示しない(サムネイル表示OFF)**」にしました(チェックを外すと出ます。選んだものを覚えます)。
  - 「面付けする」を「詳細設定」の中へ、「綴じ方向」と「用紙」を「詳細設定」の外(画面を開いてすぐ見える所)へ移しました。面付けしないときは用紙を選べません。
  - 「大きさの基準」に「**ページ指定**」を足しました(何ページ目の大きさに合わせるかを選びます。大きさはいつでも選べるよう、詳細設定にいつも出します)。
  - 「ファイル名」の欄を分かりやすくしました。**出力すると、本体と付属の2つの PDF ができることがあります**:
    本体(本のページを読む順・面付けの順に並べたもの。いつも作ります)と、付属(表紙・帯などの付属の役割を付けたページだけを集めたもの。
    付属のページがあって「付属の出力」が「別の PDF にする」のときだけ作ります)。それぞれの名前を、欄の横にそのまま表示します
    (例: `本_製本_面付け.pdf` と `本_付属.pdf`。付属のページが無いときは「いまは作りません」と出ます)。
  - 「カバー・表紙・帯などのページ」の項目を、詳細設定の「**カバー・表紙・帯などの項目**」で決められるようにしました:
    項目の**追加・削除**(追加した項目は、名前と使い道を決められます。例: 口絵)、**表示する・しない**、**複数のページを選べるか**、並び(↑↓)。
    カバーの表紙・裏表紙は本の最初・最後の1ページなので、複数にはできません。決まった項目は消せませんが、隠せます。
- **スキャンの整え**
  - 「スキャンを整える」の画面に「**本を読む向き**」(右から左 / 左から右)と「**PDF の1ページ目**」(本の最初のほうの見開き / 最後のほうの見開き)を作りました。
    選んだ向きで、見開きのどちらのページを先にするかと、ビューアでの見開きの並び(右綴じ・左綴じ)を決めます。
    1ページ目を変えたときは、本の最初のページから表示します。PDF ごとに覚えます。初期値は詳細設定で決められます。
  - お送りいただいた国語(2018)のスキャンで、表示がおかしくなる原因が分かりました。本を強く押さえてスキャンしたため、ノドが真ん中では白く写り、
    紙の上の端・下の端にだけ影が残っていました。このため見開きと判断できず(「ばらした冊子」と判断していました)、太い罫線をノドと間違えるページもありました。
    紙の上の端・下の端のノドの影を探すようにして、6枚すべてで正しい位置(幅の 50〜51%)で分けられるようになりました。
  - **余白の精度**: ノドの影がページの中まで続くときは、ページの内側の端を影の外へ寄せるようにしました(中身には 1mm 以上の余白を残します)。
    上の端・下の端のノドの影は、中身にかからない部分を白く覆います。国語のスキャンでは、左のページの内側に残っていた灰色の帯が無くなりました。
    影が文字の下まで続いている部分は、文字を切らないため残ります(画像は作り直さないため、影を薄くすることはしません)。
- **詳細設定**: 12の項目の目次をやめ、入口を4つの大きな分類にしました。分類を選ぶと、その分類の項目だけが出ます。
  1. 開く・読む(起動・表示・電子書籍とコミック) 2. スキャン・ページ操作(スキャンの整え・コピーと画像・ページ収集)
  3. 印刷・製本出力(印刷の画質・製本用PDF出力・付属とファイル名) 4. 詳細管理・トラブル対応(強制ダウンロード対策・データ管理・動作確認・この拡張について)
- **ダークモードの確認**: ビューア(ツールバー・メニュー・右クリック・各ダイアログ・パネル・サイドバー・検索)・詳細設定・初回案内・電子書籍リーダーを
  ダークモードで撮って確かめました。読めなかったのは選択欄の一覧だけで、ほかは問題ありませんでした。

### 0.4.2(実機での確認を受けた修正と追加)

- **編集してから保存すると、ファイル名が `e0116df8-faee-4f32-a24f-2834ac77ee52.pdf` のようになる**:
  原因は Chrome の不具合です。ほかの拡張機能(ダウンロード管理など)が「ダウンロードするファイルの名前を決める機能」を使っていると、
  拡張機能が Chrome のダウンロードの仕組みで保存するときに指定した名前が無視され、英数字の羅列(GUID)になります
  (製本ビューアだけを入れた Chrome では起きず、名前を決める機能を使う拡張機能を一緒に入れると起きることを確かめました)。
  編集していないときの保存(元の PDF のダウンロード)は別の仕組みなので、起きていませんでした。
  - **保存先を選んで保存するもの**(編集した内容の保存・整えた PDF・コミックから作った PDF・ほかの形式への変換・元のファイルの保存・電子書籍リーダーの保存)は、
    ダウンロードの仕組みを使わず、Chrome の「名前を付けて保存」の画面で選んだファイルに直接書き込むようにしました。ほかの拡張機能の影響を受けません。
    すでにあるファイルを選んだときは「置き換えますか」と確かめる画面が出ます(確かめずに上書きはしません)。
    この保存はダウンロードの一覧には残らないため、保存のお知らせに「フォルダを開く」は出ません。
    保存する PDF を作るのに時間がかかったときは(Chrome は、クリックの直後でないと保存先を選ぶ画面を出せません)、
    「保存の準備ができました」のお知らせの「**保存先を選ぶ**」を押してください。
  - **保存先を聞かずにダウンロードフォルダに保存するもの**(製本用PDF出力・このページだけの PDF・画像・ZIP・設定の書き出し)は、これまでどおりダウンロードフォルダに保存し、
    名前が英数字の羅列になったときだけ、そのファイル(いま作ったもの)を消して、保存先を選ぶ画面で保存し直します。
    製本用PDF出力のように複数のファイルを作るときは、保存先の**フォルダ**を選ぶ画面になり、同じ名前のファイルがあれば「名前 (1).pdf」にします。
    一度そうなったことは覚えておき、7日間は最初から保存先を選ぶ画面を使います(ほかの拡張機能を外したときのため、7日たつと元に戻して確かめ直します)。
  - 「PDF としてコピー」は、補助プログラムがあれば補助プログラムが保存するので影響を受けません。補助プログラムが無いときのコピーだけは、
    ダウンロードの仕組みしか使えないため、名前が英数字の羅列になることがあります。
- **左上の名前をクリックして名前を変更**: ツールバーの左上の名前(PDF の中の題名。無ければファイル名)をクリックすると、その場で書き換えられます。
  Enter(またはほかの場所をクリック)で決定、Esc でやめる、空にして決定すると元の名前に戻ります。
  変えた名前は、タブの名前と左上に出て、「**保存**」ボタンが出ます。保存すると、PDF の中の名前(題名。文書のプロパティの「タイトル」)として書き込みます
  (PDF に2か所ある題名 = 文書情報と XMP の両方を書き換えるので、Acrobat などで開いても新しい名前になります)。
  ファイル名は変えません(保存の名前の候補は、これまでどおり `元の名前_編集済み.pdf`。保存先を選ぶ画面で自由に変えられます)。
  変更のお知らせの「元に戻す」で、変える前の名前に戻せます。パスワード付きの PDF など、題名を書き込めない PDF では、名前は元のままで保存し、そう知らせます。

### 0.4.1(実機での確認を受けた修正)

- **パソコン内の EPUB などを開くと保存先を聞かれる**: Chrome は表示できない種類のファイル(EPUB・MOBI・AZW3・CBZ・CBR など)を開くと、
  同時に「ダウンロード」も始めます(「保存する前に保存場所を確認する」がオンだと保存先を聞く画面が出ます)。製本ビューアで表示するので、
  そのダウンロードは保存先を決める前に取り消すようにしました(保存先を聞く画面は出ず、ダウンロードの一覧にも残りません)。
- **「PDF としてコピー」「画像としてコピー」がダウンロードフォルダに保存される**: コピーは使い捨てにしました。
  補助プログラムがあるときは、見えない一時フォルダ(Windows は `%TEMP%\seihon-viewer-copy`)に置いてクリップボードに入れ、
  次にコピーすると前のファイルは消えます。「ダウンロード」フォルダには何も残らず、ダウンロードの一覧にも出ません。
  補助プログラムが無いときは、これまでどおり「ダウンロード」の「製本ビューア_コピー」に保存しますが(拡張機能だけではファイルをクリップボードに入れられないため)、
  保存している間はダウンロードの表示を出さず、次にコピーすると前のファイルを消します。補助プログラムは、拡張機能のフォルダを置き換えるだけで新しい版になります(入れ直しは不要)。
- **右綴じ(縦書き)のスキャンが最後のページから始まる**: 右綴じの本を、横書きの本と同じ向きにページをめくってスキャンすると、
  最後の見開きが先になります。ツールバーの「分割表示」→「**ページの順を逆にする**」(または「整え方を変える…」の「最後の見開きから順にスキャンした」)で、
  見開きの順を逆にできるようにしました(見開きの中は右のページが先のまま。PDF ごとに覚えます)。右綴じに切り替えたときにも案内を出します。
- **スキャンの下の余白**: 紙の端(紙の外のふた・台との境目、外側の縁の影の帯の幅が変わるところ)を探し、紙の外は切り取るようにしました。
  お送りいただいたサンプル2は、1ページが 176×257 mm から 171×250 mm になり、紙の下の端・外側の端でぴったり終わります。

### 0.4(追加のご依頼のフェーズ2の後半: 電子書籍・コミックの表示と変換)

ご依頼の形式ごとの対応は次のとおりです。

| 形式 | 表示 | PDF への変換 | 備考 |
|---|---|---|---|
| EPUB(文字の本) | ○ 電子書籍リーダー(縦書き・右から左へめくる・目次・検索・文字の大きさ・背景の色) | ○ 「PDF に保存」(Chrome の印刷画面で「PDF に保存」。文字を検索・選択できる PDF) | |
| EPUB(画像だけの本。漫画・写真集など) | ○ 製本ビューア(PDF にして表示) | ○ 画像をそのまま並べた PDF(画質は元のまま) | 固定レイアウトの漫画の EPUB の多くはこちら |
| MOBI・AZW | ○ 電子書籍リーダー | ○ 「PDF に保存」 | DRM(コピー防止)の無いものだけ |
| AZW3(KF8) | ○ 電子書籍リーダー | ○ 「PDF に保存」 | DRM の無いものだけ |
| KFX | × | × | Amazon の独自形式で、仕様が公開されておらず、使える部品もないため。開くと理由を表示します |
| CBZ(画像の ZIP) | ○ 製本ビューア(PDF にして表示) | ○ 画像をそのまま並べた PDF | ComicInfo.xml の読む向き(漫画は右綴じ)に従います |
| CBR(画像の RAR) | ○ 製本ビューア(PDF にして表示) | ○ 画像をそのまま並べた PDF | RAR4・RAR5。パスワード付きは開けません |
| (おまけ)CB7・FB2 | ○ | ○ | CB7 は画像の 7z、FB2 は FictionBook |

- **コミックは PDF にして表示**: CBZ・CBR と画像だけの EPUB は、画像を作り直さずに並べた PDF にして、いつもの製本ビューアで表示します。
  製本表示(表紙が単独)・右綴じ・印刷・ページ役割・コピー・ページ収集など、PDF と同じ機能がすべて使えます。
  JPEG は元のデータのまま入れるので画質は変わりません(試験で、PDF の中の JPEG が元の画像とまったく同じことを確かめました)。
  見開きの画像(横長の 1 枚)は、同じ画像の右半分・左半分を表示する 2 ページに分けます(右綴じなら右半分が先。画像は作り直しません)。
  ダウンロードボタン →「PDF として保存…」で、`元の名前.pdf` として保存できます。200 ページ・48MB の CBZ でも、この環境で 1.5 秒ほどで表示できました。
- **文字の本は電子書籍リーダーで表示**: EPUB・MOBI・AZW・AZW3 は、新しく作った「電子書籍リーダー」の画面で表示します。
  縦書きの本は縦書きのまま、右から左へめくります(← キーで次のページ)。目次・本の中の検索・文字の大きさ・背景の色(白・セピア・黒)・
  単ページ/見開き、読んだ位置の記憶があります。「**PDF に保存**」で、本を紙の大きさ(文庫・新書・A5・B5・A4)に並べ直して
  Chrome の印刷画面を開きます。送信先で「PDF に保存」を選ぶと、文字を検索・選択できる PDF になります(縦書きは縦書きのまま)。
- **PDF からの変換**: ⋮ メニュー →「**ほかの形式に変換して保存…**」(コミックなどを表示しているときはダウンロードボタンからも)で、
  表示している PDF を **画像(ZIP)・コミック(CBZ)・EPUB(固定レイアウト)・テキスト(.txt)** にして保存できます。
  スキャンのページは元の JPEG をそのまま使います(画質は元のまま)。EPUB には PDF のしおりが目次として入ります。
  MOBI・AZW3・KFX(Kindle の形式)への変換はできません(公開されている作り方・部品がないため)。Kindle で読むときは、
  EPUB を Amazon の「Send to Kindle」で送ると Kindle の形式に変換されます。
- **開き方**: ビューアに電子書籍・コミックのファイルをドラッグ&ドロップ、⋮ →「ファイルを開く…」(Ctrl+O)、
  パソコン内のファイル(`file://`)を Chrome で開く、リンクを右クリック →「リンク先の本・コミックを製本ビューアで開く」。
- **安全のため**: 本の中のスクリプトは実行しません(拡張機能のページの決まりで止まり、念のため読み込む前にも取り除きます)。
  DRM(コピー防止)を外す処理は作っていません。DRM のかかった本は、理由を表示して開きません。

## 3. 導入方法

1. 受け取った ZIP ファイルを展開し、`seihon-viewer` フォルダを**ずっと置いておける場所**に置きます
   (例: `ドキュメント\seihon-viewer`)。Chrome はこのフォルダから直接読み込むため、後で消したり動かしたりしないでください。
2. Chrome のアドレスバーに `chrome://extensions` と入力して開きます。
3. 右上の「**デベロッパー モード**」をオンにします。
4. 「**パッケージ化されていない拡張機能を読み込む**」を押し、`seihon-viewer` フォルダ(中に `manifest.json` があるフォルダ)を選びます。
5. 「製本ビューアへようこそ」という案内のタブが開きます。案内に沿って次の2点を確認してください。
   - **ファイルの URL へのアクセスを許可する**(パソコン内の PDF を開くため、また強制ダウンロード対策の第3層のために必要)
     `chrome://extensions` の製本ビューアの「詳細」→「ファイルの URL へのアクセスを許可する」をオン。
   - **Chrome の PDF 設定**が「PDF をダウンロードする」になっていないこと
     `chrome://settings/content/pdfDocuments` で「Chrome で PDF を開く」を選びます。
6. (お好みで)ツールバーのパズルのアイコンから製本ビューアを**固定**(ピン留め)すると、アイコンをすぐ押せます。

> 案内のタブは、拡張機能のアイコンを右クリック →「使い方と初期設定の確認」でいつでも開けます。
> シークレットウィンドウで使う場合は、「詳細」→「シークレット モードでの実行を許可する」をオンにしてください。

## 4. 更新方法

1. 新しい版の ZIP を展開し、**今の `seihon-viewer` フォルダの中身をすべて置き換え**ます(フォルダの場所は変えない)。
2. `chrome://extensions` を開き、製本ビューアの「再読み込み」(丸い矢印)ボタンを押します。
3. 開いていた製本ビューアのタブや、Web ページのタブは、再読み込み(F5)してください(古い版の部品が残っているため)。

- 設定と収集したページはそのまま残ります。拡張機能の ID を固定しているため(`miiaicaobmegmjkmicojhmajnancjnjp`)、
  フォルダの場所が変わっても同じ拡張機能として扱われます。
- 「削除」を押すと、設定も収集したページも消えます。更新のときは削除しないでください。
- 0.0.1 から 0.0.2 への更新では、使う権限が増えます(下の「9. 権限とその理由」)。デベロッパーモードで読み込んだ拡張機能では、
  再読み込みするだけで新しい権限が有効になります。0.0.2 以降(0.0.3 → 0.0.4 → 0.1.0 → 0.2.0 など)の更新では、いつも使う権限は変わりません。
- 0.2.0 では、補助プログラム(6.14)を使うときだけの「任意の権限」(ネイティブ アプリとの通信)が加わりました。
  詳細設定で「補助プログラムを使えるようにする…」を押したときに、Chrome が確認を出します。使わなければ求めません。
- 0.3.0 では権限は増えません。新しい設定「スキャンの整え」(6.15)は、初期値(自動で1ページずつに分ける・余白を除く)で始まります。
- 0.4.1 では「ダウンロードの表示の変更」(`downloads.ui`)の権限が増えます(コピーの保存中にダウンロードの表示を出さないため)。
- 0.4.0 では権限は増えません。新しい設定「電子書籍・コミック」(8章)は、初期値(コミックの向きは本の情報に従う・見開きの画像を分ける・
  パソコン内の本も開く)で始まります。
- 0.1 から 0.2 に更新すると、**初期値のままだった設定**は新しい初期値になります(印刷の画質「自動」→「最高画質」、複数ページのコピー「PDF を保存」→
  「PDF としてコピー」、付属の出力ファイル名「_帯」→「_付属」)。自分で選んでいた値はそのままです。
- 念のため、更新の前に詳細設定の「設定の書き出し」で設定とページ役割を書き出しておくと安心です。

## 5. アンインストール

`chrome://extensions` で製本ビューアの「削除」を押し、`seihon-viewer` フォルダを消します。
設定と収集したページ(この拡張機能の中のデータ)も一緒に消えます。

## 6. 使い方

### 6.1 PDF を開く

| 方法 | 動き |
|---|---|
| Web の PDF のリンクを押す・URL を開く | 自動で製本ビューアで開きます |

### 6.3 製本表示

表紙(1ページ目)だけを単独で、2ページ目以降を見開きで表示します。スクロールは連続スクロールです。

```
左綴じ(初期値)              右綴じ
┌────┬────┐                ┌────┬────┐
│    │ 1  │ ← 表紙は右       │ 1  │    │ ← 表紙は左
├────┼────┤                ├────┼────┤
│ 2  │ 3  │ 偶数が左         │ 3  │ 2  │ 偶数が右
│ 4  │ 5  │ 奇数が右         │ 5  │ 4  │
│ …  │ …  │                │ …  │ …  │
│ 12 │    │ ← 総ページ数が偶数 │    │ 12 │
└────┴────┘   なら最終ページは単独 └────┴────┘
```

- 総ページ数が奇数のときは、最後の見開きがそのまま2ページで終わります。
- 表示モードの切り替えはツールバーの本のアイコンから。押すたびに **単ページ → 製本表示 → 見開き → 単ページ** と切り替わります
  (0.2 から。0.1 までは選択肢のメニューが出ていました)。「見開き」は 1-2、3-4… の通常の見開き、「単ページ」は Chrome 標準と同じ縦1列です。
- 綴じ方向は、その右の綴じ目のアイコンで切り替えます。切り替えると、その選択は詳細設定にも保存され、次から同じ向きで開きます。
- 右綴じでは、← キーで次のページ、→ キーで前のページへ進みます。拡大して横にスクロールできるときは、矢印キーで横にスクロールします。
- 「幅に合わせる」は、いちばん幅の広い見開き(単ページの表示では、いちばん幅の広いページ)が画面に収まる倍率にします。
  ページの大きさがそろっていない PDF でも、どの見開きも画面からはみ出しません。
- 「ページに合わせる」(0.2): その時点で**いちばん大きく見えているページ**を選び(見開きの表示では、見開きごとに見えている面積を比べます)、
  そのページ(見開き)が画面にちょうど収まる倍率にして、**画面の真ん中**に表示します。ページとページの間を見ているときに押しても、
  半端な位置のままにはなりません。例: 1ページ目(表紙)がいちばん大きく見えていれば、表紙だけがきれいに真ん中に表示されます
  (製本表示の表紙は、本と同じく見開きの右側の位置です)。

### 6.4 Chrome 標準ビューアとの切り替え

- 製本ビューアの「**Chrome標準で開く**」を押すと、同じタブで Chrome 標準ビューアに切り替わります(表示中のページも引き継ぎます)。
  この1回だけ自動切り替えを止める仕組みなので、次に PDF を開いたときは、また製本ビューアで開きます。
- Chrome 標準ビューアから戻るには:
  - 拡張機能のアイコン(製本ビューア)を押す
  - ページを右クリック →「製本ビューアで開く」(PDF を表示しているタブでだけ出ます)
- 特定のサイトでは常に Chrome 標準で開きたい場合は、詳細設定の「自動切り替えしないサイト」に書きます。

### 6.6 印刷とダウンロード

- **ダウンロード**は元の PDF ファイルをそのまま保存します(作り直しません)。ページを削除したり、注釈やフォームを書き込んだりしたときは、
  「編集した内容を含めて保存…」「元のPDFを保存」を選ぶメニューが出ます。編集した内容の保存は、保存先を選ぶ画面を出して新しいファイルとして行います(6.12)。
- **印刷**(印刷ボタン・Ctrl+P)は、詳細設定の「印刷の画質」で方式が変わります。
  - **元の PDF で印刷**(おすすめ・0.2 からの初期値。0.7.0 までの名前は「最高画質」): 元の PDF を、そのまま Chrome の印刷機能で印刷します。画像は元の解像度、文字は文字のまま印刷されます。
    印刷画面の「送信先」で「**PDF に保存**」を選ぶと、元の画質のまま、**OCR の文字も残った PDF** になります(検索・文字の選択ができる)。
    ページを削除したり書き込んだりしていれば、その内容を反映した PDF を印刷します。保存するときのファイル名の候補は、PDF の題名(無ければファイル名)です。
  - **画像として印刷(高画質 / 標準 / 自動)**: 0.1 までと同じ PDF.js の方式で、全部のページを画像(300dpi / 150dpi)にして印刷します。
    「PDF に保存」すると文字も画像になります。元の PDF で印刷 できなかったとき(Chrome の PDF 設定が「PDF をダウンロードする」になっているときなど)も、この方式になります。
  - ブラウザのメニュー(︙ →「印刷」)から印刷したときは、いつも画像にして印刷します(元の PDF で印刷 の設定のときは 300dpi)。
  - ページ数の多い PDF で時間がかかる・崩れる場合は、印刷準備中の画面の「Chrome標準ビューアで印刷」、または ⋮ メニューの「Chrome標準ビューアで開いて印刷」も使えます。
- 0.0.4 までは、印刷すると1ページ目(表紙)しか印刷されませんでした(画面用の指定が印刷にも効いていたため)。0.1 で直しました。

### 6.7 右クリックメニューとコピー

ページの上で右クリックすると、製本ビューアのメニューが出ます。

| 項目 | 動き |
|---|---|
| 選択した文字をコピー | 文字を選んでいるときだけ出ます。選んだ文字をコピーします(通常のコピー) |
| リンクを新しいタブで開く / リンクのアドレスをコピー | リンクの上で右クリックしたときだけ出ます |
| **コピー**(Ctrl+Shift+C) | このページを画像にしてクリップボードに入れます。チャット欄や文書に Ctrl+V で貼り付けられます(0.1 までの「AI用にコピー」) |
| 画像として保存 | このページを画像ファイルとして保存します(元データ優先のスキャンのページは元の JPEG、それ以外は PNG) |
| 収集に追加 / 収集から外す | ページ収集に入れる・外す(下記 6.8) |
| 収集を表示 | ページ収集のパネルを開きます |

- **Shift を押しながら右クリック**すると、Chrome の通常のメニュー(翻訳・検証など)が出ます。
  フォームの入力欄の上では、貼り付けなどができる通常のメニューが出ます。
- サムネイルを **Ctrl+クリック・Shift+クリック**(またはサイドバーの「選択」)で複数選ぶと、サイドバーの下に操作バーが出ます。
  選んだページを右クリック(または操作バー)で、まとめて「削除」「役割を付ける」「コピー」「PDF としてコピー」「画像としてコピー」「収集に追加」ができます。
- ページの右クリックメニューの最後に「このページを削除」があります(6.12)。
- **コピーの形式**(詳細設定の「コピー・画像」で変更可):
  - 1ページ: 画像をクリップボードへ(初期値) / PDF をファイル保存 / 画像をファイル保存
  - 複数ページ: **PDF としてコピー**(初期値。1つの PDF にして、ファイルとしてクリップボードへ) / 画像としてコピー / PDF をファイル保存 / 画像を ZIP で保存
- **PDF としてコピー・画像としてコピー**: ファイルを作って保存し、クリップボードに入れます(しくみと補助プログラムは 6.14)。
  - 補助プログラムがあるとき: ファイルそのものがクリップボードに入ります(エクスプローラー・Finder の「コピー」と同じ)。
    フォルダ・チャット欄・メールなどに Ctrl+V で貼り付けられます。
  - 補助プログラムが無いとき: Chrome のダウンロードで保存し、保存したファイルの**場所(パス)**を文字でクリップボードに入れます。
    アップロードなどの「ファイルを選ぶ画面」の「ファイル名」の欄に貼り付けると、そのファイルを選べます。複数のファイルのときは、フォルダの場所が入ります。
  - 保存先(0.4.1 から): 補助プログラムがあるときは、見えない一時フォルダ(Windows は `%TEMP%\seihon-viewer-copy`)。
    無いときは、ダウンロードフォルダの中の「**製本ビューア_コピー**」フォルダです(複数の画像は、その中に名前の付いたフォルダを作ってまとめます)。
    名前は `元ファイル名_抜粋_日時.pdf` など。**コピーは使い捨て**で、次にコピーすると前のコピーのファイルは消えます(貼り付けたものはそのまま残ります)。
  - 「画像としてコピー」で1ページだけのときは、画像そのものをクリップボードに入れます(補助プログラムは要りません)。
- **画像にする画質**(詳細設定の「画像にする画質」。0.7.0 から dpi を基本に):

  | 画質 | 大きさ |
  |---|---|
  | **元データ優先**(初期値・今までの「最高画質」) | スキャンしたページ(画像のページ)は元の画像と同じ解像度。文字・図のページは 600dpi(画像を含むときは、画像の解像度と高い方)。OCR の見えない文字は、文字・図として数えません |
  | 高画質 | 300dpi で描く(0.6.8 までは長辺 2400 ピクセル。A4 ではどちらも約 2480×3508 ピクセルでほぼ同じ) |
  | 標準 | 150dpi で描く(0.6.8 までは長辺 1600 ピクセル。A4 では 1240×1754 ピクセル)。ファイルが小さい |
  | 指定する | dpi(100〜1200)で描く(0.6.8 までは長辺のピクセル数・倍率。0.7.0 への更新で dpi に換算して引き継ぐ) |

  画像は劣化しない PNG(可逆圧縮)で、画面に見えているとおり(回転・書き込んだ注釈・フォームの入力内容を含む)に作ります。
  元データ優先でファイルに保存するときは、ページが1枚の JPEG 画像だけでできていれば(回転・書き込みが無いとき)、元の JPEG をそのまま取り出します。
  1枚の画像は最大 6400 万画素までにします(それより大きくなる場合は縮めます)。
- クリップボードに入れられなかったときは、自動で解像度を下げて再挑戦し、それでも駄目なら画像ファイルとして保存して知らせます。
- 保存したファイルは、Chrome のダウンロード先のフォルダに入ります。同じ名前のファイルがあるときは「名前 (1).pdf」のように
  別の名前になり、上書きはしません(0.4.2: ほかの拡張機能の影響で名前が英数字の羅列になるときは、保存先を選ぶ画面になります)。

### 6.8 ページ収集

いろいろな PDF の必要なページを裏で溜めておき、まとめて取り出す機能です。

- **追加する**: ページやサムネイルを右クリック →「収集に追加」/ サムネイルを複数選んで追加 /
  収集パネルの「この PDF から追加」に範囲(例: `3-7, 10`、`5-` は5ページ目から最後まで)を入れて「追加」 /
  「この PDF を全部追加」。すでに収集にあるページは重ねて追加しません。
- **パネル**(ツールバーの収集ボタン): 収集したページの一覧(小さな見本つき)。ドラッグまたは ↑↓ で並べ替え、ゴミ箱で削除、
  「すべて消す」で全消去。
- **コピーする**(0.2): パネルの下の「コピー」の「**PDF としてコピー**」で1つの PDF に(元の文字・図形のまま。OCR の文字も残る)、
  「**画像としてコピー**」でページごとの画像にして、裏で保存し、クリップボードに入れます(6.7 の「PDF としてコピー・画像としてコピー」)。
- **保存する**: 「保存」の「PDF で保存」で1つの PDF に、「画像(ZIP)で保存」でページごとの画像を ZIP に(0.1 までの「PDF で書き出し」「PNG(ZIP)」)。
  ファイル名は `元ファイル名_抜粋_日時.pdf`(複数の PDF をまたぐときは `元ファイル名ほか_抜粋_日時.pdf`)。
  コピー・保存した後も収集は残ります(詳細設定で「自動で空にする」にもできます)。
- **保存**: 収集は拡張機能の中のデータベースに保存され、ブラウザを閉じても残ります。複数の PDF をまたげます。
  あとで書き出せるよう元の PDF も保存しますが、同じ PDF は内容で見分けて1回だけ保存します。
  保存の上限(初期値 1GB)を超えて追加しようとすると確認が出ます。上限は詳細設定で変えられます。

### 6.9 ページ役割

製本用PDF出力で「どのページをカバー・表紙・帯などとして扱うか」を決めるための印です(0.2 で名前を変え、3つ足しました)。

| 役割(0.1 までの名前) | 意味 | 製本用PDF出力での扱い(初期値) |
|---|---|---|
| カバーの表紙(表紙) | カバーの表側 | 本体の**最初のページ**。候補が複数あるときは出力時に選ぶ |
| カバーの裏表紙(裏表紙) | カバーの裏側 | 本体の**最後のページ**。候補が複数あるときは出力時に選ぶ |
| 表紙(帯表紙) | 本そのものの表紙(カバーの下) | 付属 |
| 裏表紙(帯裏表紙) | 本そのものの裏表紙 | 付属 |
| 帯(帯) | 本に巻く帯。何枚でも | 付属 |
| 表紙の折り返し(0.2 で追加) | カバーの表側の折り返し | 付属 |
| 裏表紙の折り返し(0.2 で追加) | カバーの裏側の折り返し | 付属 |
| しおり(0.2 で追加) | しおり | 付属 |

「付属」のページは本体には入れず、別の PDF(`元名_付属.pdf`。0.1 までは `元名_帯.pdf`)に、元のページの順で入れます。
付属の役割ごとに、使い道(付属として出力 / 最初のページの候補 / 最後のページの候補 / 出力しない)を変えられます(6.10)。
0.1 までに付けた役割は、新しい名前でそのまま引き継がれます(保存している役割の中身は変わりません)。

- **付け方**(どれでも同じです):
  - **サイドバー**: ☰ でサムネイルを出し、見出しの「選択」を押してページを選び、下の操作バーのラベルのボタン →「カバーの表紙」「帯」など。
  - **製本用PDF出力の画面**: 「カバー・表紙・帯などのページ」の欄で、全部のページから選びます。帯は何ページでも選べます(6.10)。
  - **右クリック**: ページやサムネイルを右クリック →「ページ役割: …」→ 役割を選ぶ。
  - **一覧のパネル**: ⋮ メニューの「ページ役割(カバー・表紙・帯など)の一覧」から付け外しできます。
- ページを削除しても、役割はそのページに付いたままです(ページ番号が変わっても、そのページの役割として扱います)。
- 1ページに付けられる役割は1つです。同じ役割を複数のページに付けられます。
- 役割は PDF ごとに保存され、同じ PDF を開き直すと復元されます。PDF は URL ではなく内容で見分けるので、
  別の場所から開いた同じ PDF でも復元されます。
- 役割を付けていない PDF でも製本用PDF出力は使えます(1ページ目を本の最初のページ、最後のページを本の最後のページとして扱います)。
- サムネイルのバッジは短い名前です(カバー表・カバー裏・表紙・裏表紙・帯・表折返・裏折返・しおり)。マウスを置くと正式な名前が出ます。
- 役割を保存している PDF の一覧は、詳細設定の「保存しているデータ」で確認でき、PDF ごとに、またはすべて消せます。

### 6.10 製本用PDF出力

ツールバーの「製本用PDF出力」(本と下向き矢印のアイコン)で画面を開き、「**出力**」を押すだけで初期設定どおりに作れます。

- **画面の並び(0.5)**: 上から、カバー・表紙・帯などのページ / 綴じ方向 / 用紙 / 注意 /「出力ページのプレビューを表示しない(サムネイル表示OFF)」(初期値はオン)/ プレビュー /
  詳細設定(面付け・両面の綴じ方向・白紙を入れる位置・大きさの基準・付属の出力・ファイル名・カバー・表紙・帯などの項目)。
- **カバー・表紙・帯などのページ**(画面の上の欄): カバーの表紙・カバーの裏表紙・表紙・裏表紙・帯・表紙の折り返し・裏表紙の折り返し・しおりに使うページを、
  全部のページから選べます。役割の付いたページには「1ページ目(カバーの表紙)」のように役割を添えて出します。ページを選ぶと、そのページにその役割を付けて保存します
  (サイドバーのバッジにも出ます)。カバーの表紙・裏表紙は「自動」にすると、その役割のページ(無ければ役割の無い最初・最後のページ)を使います。
  ほかの欄は「なし」で、その役割を外します。
- **帯(複数可)**: 選んだページが「3ページ目 ×」のように並び、「+ ページを追加」で何ページでも足せます。× でそのページを帯から外します。
- **項目の追加・削除・複数選択(0.5)**: 詳細設定の「カバー・表紙・帯などの項目」の表で、項目ごとに「表示」(この画面・右クリック・役割の一覧に出すか)、
  「複数」(何ページでも選べる欄にするか)、並び(↑↓)を決められます。「項目を追加」で新しい項目(例: 口絵)を作れ、名前と使い道(付属として出力など)を決められます。
  追加した項目は「削除」で消せます(その項目を付けたページは、役割の無いページ = 本文に戻ります)。カバーの表紙・裏表紙は1ページだけで、決まった項目は消せません(隠せます)。
  同じ表は、拡張機能の詳細設定(「印刷・製本出力」→「付属・ファイル名」)にもあります。
- ページを削除していれば、残したページだけで本を組みます(ページ番号はサムネイルの番号)。

1. **本体の組み立て**: 最初のページ(カバーの表紙)+ 本文 + 最後のページ(カバーの裏表紙)。本文は「役割の付いていないページ」を元の順番で並べたものです。
2. **白紙の挿入**: 本体のページ数が4の倍数になるよう、0〜3枚の白紙を入れます(初期値は最後のページの直前)。
   「詳細設定」で「最初のページの直後」や「何ページ目の後ろ」(複数の場所に分けられる)に変えられます。並びはプレビューで確認できます。
3. **面付け**(初期値: する): 中綴じ用に、用紙1枚の表裏に4ページを配置します。N ページの本の k 枚目は、
   表面が左 N−2(k−1)・右 2k−1、裏面が左 2k・右 N−2k+1 です(例: 8ページなら 1枚目の表 (8,1)・裏 (2,7)、2枚目の表 (6,3)・裏 (4,5))。
   右綴じでは左右が入れ替わります。面付けをしない場合は、白紙を入れた読む順の PDF を出力します(プリンターの小冊子印刷用)。
4. **付属**: 表紙・裏表紙・帯・折り返し・しおりの役割のページは、別の PDF(付属)にします(詳細設定で「本体の後ろに入れる」「出力しない」も選べます)。
   付属は面付けせず、ページ数にも数えません。

- **付属の役割の使い道**: 付属の役割ごとに、出力での使い道を選べます(出力の画面の「詳細設定」と、拡張機能の詳細設定)。

  | 使い道 | 動き |
  |---|---|
  | 付属として出力(初期値) | 本体には入れず、付属の PDF(または本体の後ろ)に入れる |
  | 最初のページの候補 | そのページを本の最初のページとして使う(カバーではなく本の表紙を最初のページにする場合など。「カバーの表紙」の欄で候補のどれを使うか選べる) |
  | 最後のページの候補 | そのページを本の最後のページとして使う |
  | 出力しない | どの PDF にも入れない |

- **用紙**: 元のページ2枚を横に並べて収まる用紙を自動で選びます(A5 の本なら A4 横、B5 の本なら B4 横)。画面の上の「用紙」で変えられます(面付けするときだけ)。
  各ページは用紙の半分に、縦横比を保って中央に配置します。ページの大きさがそろっていないときは注意が出ます。
- **大きさの基準**(詳細設定): ページの大きさがそろっていないとき、「最も多い大きさ」「最初のページ」「ページ指定(何ページ目か選ぶ)」のどれに合わせるか。
- **両面の綴じ方向**: 初期値は横向きの用紙に合う「短辺とじ」。プリンターが長辺とじしかできない場合は「長辺とじ」にすると、
  裏面を上下逆さまに作るので、長辺とじで印刷して正しい向きになります。
- **出力したあと**、プリンターの設定(用紙・両面・とじ方・倍率 100%)が画面に表示されます。印刷した紙を順に重ねて
  真ん中で二つ折りにすると本の順番になります。
- **ファイル名**: 出力する PDF は、**本体**と**付属**の2種類です。本体はいつも作り、付属は付属のページがあって「付属の出力」が「別の PDF にする」のときだけ作ります。
  本体は `元名_製本_面付け.pdf`(面付けしない場合は `元名_製本.pdf`)、付属は `元名_付属.pdf`(0.1 までは `元名_帯.pdf`)。
  詳細設定の「ファイル名」の欄に、いまの設定でできる名前がそのまま出ます。
  同じ名前のファイルがあっても上書きせず、`元名_製本_面付け (1).pdf` のように別の名前で保存します。元の PDF は変更しません。
- 元の文字・図形・画像をそのまま配置するので、画像にはなりません(拡大しても文字がぼやけない)。
  フォームの入力内容や書き込んだ注釈は、印刷される見た目で面付けした PDF に入ります。

### 6.11 設定の書き出し・読み込み

詳細設定の「設定の書き出し・読み込み」で、設定とページ役割を1つのファイルにまとめて移せます。

- **書き出し**: 「詳細設定」「ページ役割」のどちらを入れるかを選んで「ファイルに書き出す」を押すと、
  `製本ビューアの設定_日時.json` が Chrome のダウンロード先のフォルダに保存されます。収集したページと元の PDF、速度ログは入りません。
- **読み込み**: 「ファイルを選んで読み込む…」でファイルを選ぶと、書き出した日時と、今と違う設定の項目・ページ役割の件数が表示されます。
  確かめてから「読み込む」を押します(やめることもできます)。
  - 設定は、ファイルにある項目だけを置き換えます(古い版で書き出したファイルに無い項目は、今の設定のまま)。
    範囲外などで使えない値は初期値にして、その数を知らせます。
  - ページ役割は、同じ PDF の役割を置き換え、ほかの PDF の役割は残します。開いているビューアにもすぐ反映されます。
  - 製本ビューアのファイルではないもの、壊れたファイル、新しい版の製本ビューアで書き出したファイルは読み込まず、理由を表示します。

### 6.12 ページの選択と削除・保存(0.1)

**ページを選ぶ**

- ☰ でサイドバー(サムネイル)を開き、上の見出しの「**選択**」を押します(⋮ メニューの「ページを選ぶ」でも同じ)。
  各サムネイルの左上に丸が出ます。サムネイルか丸を押すとチェックが付き、もう一度押すと外れます(Shift+クリックで範囲)。
  選択の状態では、サムネイルを押してもページへは移動しません。見出しの「すべて選択」「完了」で、全部選ぶ・選択の状態を終えます。
- 選択の状態でなくても、サムネイルにマウスを置くと左上に丸が出て、押すとそこから選び始められます。Ctrl+クリック・Shift+クリックでも選べます。
- 選んでいるときは、サイドバーの下に操作バーが出ます:

  | ボタン | 動き |
  |---|---|
  | ゴミ箱 | 選んだページを削除(Delete キーでも) |
  | ラベル | 選んだページに役割(カバーの表紙・表紙・帯・しおりなど)を付ける・外す |
  | コピー / 収集に追加 | 選んだページをコピー(初期値は PDF としてコピー)/ 収集に追加 |
  | × の四角 | 選択を解除(Esc でも) |

**ページを削除する**

- サムネイルにマウスを置くと右上に ✕ が出ます。押すとそのページを削除します。ページの右クリックメニューの「このページを削除」でも削除できます。
- 削除すると、本文の表示・サムネイル・ページ数・見開きの組み合わせがすぐに組み替わります。元の PDF のファイルは変わりません。
- 削除の直後は、サイドバーの上に「○ページ目を削除 **元に戻す**」が出ます。戻せるのは**直前の1回の削除**だけです
  (次に別のページを選ぶ・削除する・保存すると、戻せなくなります)。
- 全部のページは削除できません(少なくとも1ページは残します)。
- このビューアで書き込んだもの(ペン・蛍光ペン・テキスト)があるページを削除するときは、確認が出ます。書き込みもページと一緒に消え、
  ページの削除を「元に戻す」で取り消しても、書き込みは戻りません。ほかのページの書き込みは、そのページに付いたままです。
- ページを削除した後も、印刷・コピー・収集・製本用PDF出力・ページ役割は、表示しているページ(残したページ)を対象にします。

**保存する**

- ページを削除したり、書き込んだり、フォームに入力したりすると、ツールバーに「**保存**」ボタンが出て、タブの名前の先頭に「* 」が付きます。
- 「保存」(または Ctrl+S、ダウンロード →「編集した内容を含めて保存…」)を押すと、**保存先を選ぶ画面**が出ます。
  名前の候補は `元の名前_編集済み.pdf` です。保存先とファイル名を選んで保存すると、表示しているとおりの PDF(残したページだけ、
  書き込み・フォームの入力内容を含む)が新しいファイルとして保存されます。元の PDF のファイルは**勝手に上書きしません**
  (同じ名前のファイルがある場所を選んだときは、パソコンの保存画面が上書きしてよいかを聞きます)。
- 保存すると「保存」ボタンと「* 」は消えます。保存先を選ぶ画面でやめたときは、編集した内容はそのまま残ります。
- 保存した PDF を開き直したときにもカバー・表紙・帯などの役割が残るよう、保存した PDF にも役割を写しておきます。

**保存していない変更があるとき**

- 別の PDF を開く(Ctrl+O・ドラッグ&ドロップ)、「Chrome標準で開く」を押す、といった操作の前に、
  「**変更を保存しますか?**」(保存する… / 保存しない / キャンセル)が出ます。「保存する…」は保存してから続けます。
- タブの × や Ctrl+W で閉じる・再読み込み・別のページへ移るときは、Chrome の確認画面(「このサイトを離れますか? 行った変更が保存されない可能性があります。」)が出ます。
  Chrome の決まりで、このときに製本ビューア独自の画面(「保存しますか?」)を出すことはできません。「キャンセル」を押してタブに戻り、「保存」を押してください。
  (0.5 で ⋮ メニューの「PDFを閉じる」は外しました。閉じる前に「保存」ボタンで保存してください)

### 6.13 元のリンク・ファイルの場所のコピー(0.2)

ツールバーのファイル名の右の**鎖のボタン**(または ⋮ →「元のリンク・ファイルの場所をコピー…」)で、開いている PDF の元の場所をコピーできます。
メニューの上には、元の場所が表示されます。項目にマウスを置くと、コピーする文字が出ます。

| 開き方 | コピーできるもの |
|---|---|
| Web の PDF | **リンクをコピー**(PDF の URL)/ 2ページ目以降を見ているときは「**このページ(Nページ目)へのリンクをコピー**」(`#page=N` 付き。開くとそのページから表示) |
| パソコンの PDF(ダブルクリック・`file://`) | **ファイルの場所をコピー**(例: `C:\Users\…\本.pdf`)/ **フォルダの場所をコピー**(例: `C:\Users\…`)/ **ファイル名をコピー** / file:// のリンクをコピー |
| サイトに保存させられた PDF(強制ダウンロード対策 第3層) | 上に加えて、ダウンロード元のリンク・ダウンロードしたページのリンクをコピー、保存されたフォルダを開く |
| 「ファイルを開く」・ドラッグ&ドロップで開いた PDF | **ファイル名をコピー** だけ(ブラウザの決まりで、選んだファイルの場所はページに知らされません。場所が要るときは、エクスプローラーなどでファイルをダブルクリックして開いてください) |

### 6.14 補助プログラム(ファイルをクリップボードに入れる。0.2)

ブラウザの決まりで、拡張機能だけでは**ファイル**(PDF や画像のファイル)をクリップボードに入れられません(入れられるのは文字と画像1枚だけ)。
「PDF としてコピー」「画像としてコピー」で、貼り付けたときに**ファイルとして貼り付く**ようにするには、拡張機能のフォルダの `helper` にある
小さな補助プログラムを入れます。入れなくても製本ビューアは使えます(そのときは、ファイルの場所を文字でクリップボードに入れます)。

**入れ方**

1. 詳細設定 →「コピー・画像」→「補助プログラム」で「**補助プログラムを使えるようにする…**」を押し、Chrome の確認で「許可」を押します
   (「ネイティブ アプリとの通信」の権限。補助プログラムを使うときだけの任意の権限です)。
2. 使っているパソコンのものを実行します。
   - **Windows**: `helper\windows\install.bat` をダブルクリック(Windows 10 / 11 に最初から入っている PowerShell を使います。管理者の権限は要りません)
   - **Mac**: `helper/mac/install.command` を右クリック →「開く」(最初に「開発元を確認できない」と出たら「開く」)
   - **Linux**: 端末で `sh helper/linux/install.sh`(xclip または wl-clipboard が必要です。例: `sudo apt install xclip`)
3. 詳細設定の「**もう一度確かめる**」を押し、「✓ 使えます」と出れば準備完了です。

拡張機能のフォルダを移動したときは、もう一度 2 を行ってください。やめるときは、同じフォルダの `uninstall` を実行し、
詳細設定の「使うのをやめる」で権限も外します。

**しくみ**

- 製本ビューアが作った PDF・画像のデータを、Chrome の「ネイティブ メッセージング」で補助プログラムに渡します。
  補助プログラムは、それを**見えない一時フォルダ**(Windows は `%TEMP%\seihon-viewer-copy`、Mac・Linux も一時フォルダの中)に置き、
  エクスプローラー(Finder)の「コピー」と同じ形でクリップボードに入れます。次にコピーするときに、前のコピーのファイルを消します(0.4.1。それまでは「ダウンロード」の「製本ビューア_コピー」に保存していました)。
- Chrome のダウンロードを通さないので、Chrome の「**保存する前に各ファイルの保存場所を確認する**」がオンでも、聞かれずに裏で保存します
  (補助プログラムが無いときは Chrome のダウンロードで保存するため、この設定がオンだとファイルごとに保存場所を聞かれます)。
- 同じ名前のファイルがあっても上書きしません(「名前 (1).pdf」のようにします)。ネットワークは使いません。
  補助プログラムは製本ビューアからしか呼べません(Chrome に登録する設定ファイルで、製本ビューアの ID だけを許可しています)。
- 登録するのは、Chrome に補助プログラムの場所を知らせる小さな設定ファイルだけです(Windows はこのユーザーのレジストリ、Mac・Linux はこのユーザーの Chrome の設定フォルダ)。
  中身は `helper/README.txt` にも書いてあります。

### 6.15 スキャンの整え(見開きの分割・余白の除去・冊子の並べ替え。0.3)

プリンター(コピー機)でスキャンした PDF を、読みやすく整えて表示します。画像は作り直さないので、画質は元のままです。
元の PDF のファイルは変えません(整えた PDF は、保存を選んだときだけ、新しいファイルとして保存します)。
**多くのページがある PDF では(0.8)、まずいま見ているページのまわりを調べて整えて表示し、残りのページは表示しながら順に調べて、
終わりしだい全部のページで組み直します**(終わるまでの間、まだ調べていないページは元のスキャンのまま入ります)。

**本・ノートを開いてスキャンした見開き**(サンプル1・2のようなもの)

1. PDF を開くと、まず元のスキャンが表示され、数秒後に**1ページずつに分かれた表示**に変わります
   (調べている間は、ツールバーに「整えています…」と出ます。終わると「分割表示」のボタンになります。画面が狭いときはアイコンだけ)。
2. 分ける位置はノド(綴じ目の影・線)です。まわりの余白・ふたの影・本の縁の線・ごみなどを除き、全部のページを同じ大きさにそろえます。
3. 表示は「**見開き**」になり、元のスキャンと同じ組み合わせ(サンプル1なら 16|17、18|19…)で並びます。
4. 右綴じ(縦書き)の本なら、ツールバーの綴じ方向のボタンで右綴じにすると、右のページが先になるように並べ直します。
5. **本を読む向き・PDF の1ページ目(0.5)**: ボタン →「整え方を変える…」で、「本を読む向き」(右から左に読む / 左から右に読む)と
   「PDF の1ページ目」(本の最初のほうの見開き / 最後のほうの見開き)を選ぶと、それに合わせて並べ、表示の綴じ方向も合わせます(PDF ごとに覚えます)。
   初期値は詳細設定の「スキャン・ページ操作」→「スキャンの整え」で決められます(読む向きの初期値は「ビューアの綴じ方向に合わせる」)。
6. **ノドの見つけ方(0.5)**: ノドの線・影が上から下まで写っていなくても、紙の上の端・下の端に残るノドの影から位置を決めます
   (本を強く押さえてスキャンしたもの)。ノドの影がページの中まで続くときは、ページの内側の端を影の外へ寄せます(中身は切りません)。

**ばらした中綴じの冊子を両面スキャンしたもの**(サンプル3のようなもの)

1. PDF を開くと、ツールバーに「**冊子を並べ替える**」が出ます(画面の下にも案内が出ます)。
2. 押して「冊子の順に並べ替える」を選ぶと、真ん中で2つに分けて、**表紙 → 裏表紙の順**に並べ替えます。
   製本表示で、表紙が単独、その後が見開きで並びます。
3. 並びがおかしいときは、ボタン →「整え方を変える…」で選び直せます。プレビューで1ページ目が表紙になっているか確かめてから「この方法で表示」を押してください。
   - **スキャンした順**: 外側の紙(表紙が載った紙)から / 内側の紙(真ん中の紙)から
   - **1枚ごとに、内側の面(表紙の無い側)を先にスキャンした**
   - **後からスキャンした面が上下逆さまになっている**(コピー機の両面読み取りの設定によっては、裏面が逆さまになります)
   - **綴じ方向**(左綴じ: 表紙が紙の右側 / 右綴じ: 表紙が紙の左側)
   (サンプル3は「外側の紙から・表紙のある面を先に・上下はそのまま・左綴じ」の並びでした。これが初期値です)

**傾いたスキャン(0.6)**: 縦長のスキャンが傾いていると、開いたときにまっすぐにして表示します(0.8.1。設定「スキャンした見開き」が「自動」で
「傾き」が「既定で入れておく」の初期値のとき。傾きの判断は、最初の数ページと中ほどの数ページから決めます)。
設定が「聞く」のときは、ツールバーに「傾きを直す」が出ます。押すと、傾きだけをまっすぐにして表示します
(ページの数・順は変わりません。ボタンは、整えたあとは「傾き補正表示」になります)。⋮ メニューの「スキャンを整える…」では
「**ページの分割・並べ替えを行わない**」+「**補正: 傾きをまっすぐにする**」で選びます(角度を指定して全部のページをそろえて回すこともできます)。
見開き・冊子では、分けるときに傾きも直します(0.6.0 の変更点を参照)。

**紙が余白の中に写っているもの(0.6.5)**: 写真など、紙(はがき・カード・本など)が背景の中に小さく写っているページでは、
紙のまわりの余白を切り取って表示します。開いたときに案内が出るほか、⋮ メニューの「スキャンを整える…」のダイアログで
「**ページの分割・並べ替えを行わない**」+「**補正: 余白を除く**」を選んでも使えます(縦長のページでも選べます。傾きをまっすぐにすると組み合わせられます)。
紙の範囲は、背景の明るさとの違いから見つけます。紙がページいっぱいに写っているもの(プリンターでスキャンした文書など)や、
紙の箱の外にまだ本文が残っているものは、紙の範囲と余白の区別がつかないので、そのまま表示します。

**ツールバーのボタン**(「分割表示」「並べ替え表示」など。押すとメニューが出ます)

| 項目 | 内容 |
|---|---|
| 元のスキャンに戻す | 元の PDF の表示に戻ります。この PDF は、次に開いたときも自動では整えません |
| 整え方を変える… | 整え方のダイアログを開きます(0.8 から**「ページの構成」**: 見開きを1ページずつに分割する / 冊子のページを読む順に並べ替える / ページの分割・並べ替えを行わない。**「補正」**: 余白を除く・傾きをまっすぐにする。**「条件」**: 本を読む向き・PDF の1ページ目・冊子のスキャンした順。プレビュー付き) |
| 整えた PDF を保存… | 保存先を選んで `元の名前_分割.pdf`(冊子は `_並べ替え.pdf`、余白を除いたものは `_余白.pdf`)として保存します。画質は元のまま、OCR の文字も残ります |
| (整える前)見開きを1ページずつに分ける / 余白を除いて表示 / 冊子の順に並べ替える / 整え方を選ぶ… | まだ整えていないときのメニュー |

- **保存**: ダウンロードボタン・Ctrl+S からも「整えた PDF を保存…」「元の PDF を保存」を選べます。
- **覚えておく**: PDF ごとに選んだ整え方(「元に戻す」を選んだことも含む)を覚えておき、次に開いたときも同じように表示します。
  詳細設定の「スキャンの整え」で消せます。
- **ほかの機能**: 整えた表示でも、コピー・ページ収集・ページ役割・製本用PDF出力・印刷・検索などはすべて使えます(整えたページが対象です)。
  作るファイルの名前は `元の名前_分割…` になります(例: `元の名前_分割_製本.pdf`)。
- **自動で分けたくないとき**: 詳細設定の「スキャンの整え」で「分けるかどうか聞く」(ボタンを出すだけ)か「何もしない」を選べます。
  ⋮ メニューの「**スキャンを整える(見開きの分割・余白の除去・冊子の並べ替え)…**」からは、いつでも整えられます。
- **余白を除かない**: 詳細設定またはダイアログで「余白を除く」を外すと、ノドの線だけを除いて、ノドの位置で左右に分けます(ページはスキャンの高さのまま)。
- 文字・図でできた PDF(スライドなど)では、何もしません。縦長のページの PDF では、傾いたスキャン(0.6)と、紙が余白の中に写っているもの(0.6.5)に対応します。

### 6.16 電子書籍・コミック(0.4)

**コミック(CBZ・CBR)と、画像だけの EPUB**

1. 開くと、画像を並べた PDF にして、製本ビューアで表示します(画面の下に「コミック(CBZ)を PDF にして表示しました」と出ます)。
2. 読む向きは、本の情報(CBZ・CBR の ComicInfo.xml、EPUB のページの進む向き)に従います。情報が無ければ右綴じ(日本の漫画)です。
   ツールバーの綴じ方向のボタンでも変えられます(この本を表示している間だけ。PDF を開くと設定の向きに戻ります)。
3. 画像の並びは、ファイル名の数字の順です(`2.jpg` → `10.jpg` の順。フォルダごとにまとめます)。
   macOS の付属ファイル(`__MACOSX`)・`Thumbs.db`・画像でないファイルは除きます。
4. 見開きの画像(横長の 1 枚)は 2 ページに分けます(詳細設定で分けないようにもできます)。製本表示で 2 ページが同じ見開きに並ぶよう、
   必要なら前に白紙のページを 1 枚入れます(そのときは画面の下に出ます)。
5. **保存**: ダウンロードボタン(または Ctrl+S)→「PDF として保存…」で `元の名前.pdf` として保存します。「元のファイルを保存」で元の CBZ なども保存できます。
6. 画像の扱い: JPEG・PNG はそのまま、GIF・BMP・可逆の WebP は PNG に、非可逆の WebP・AVIF は JPEG(品質 95)にして入れます
   (PDF にそのまま入れられない形式のため)。読めない画像は除いて、そのことを画面に出します。

**文字の本(EPUB・MOBI・AZW・AZW3)— 電子書籍リーダー**

| 操作 | 動き |
|---|---|
| ← / → | 左・右へめくる(右綴じの本は ← で次のページ) |
| Space・PageDown / Shift+Space・PageUp | 次 / 前のページ |
| Home / End | 本の最初 / 最後 |
| 画面の左右の端の ‹ › | 左・右へめくる |
| ☰(目次) | 目次・検索・本の情報(表紙・著者・形式など) |
| Ctrl+F | 本の中を検索(結果を押すとそこへ移る) |
| 見開きのボタン | 単ページ / 見開き(画面が広いとき 2 ページ並べる。縦書きの本は画面いっぱいに 1 ページ) |
| A− / A+ | 文字の大きさ(60〜250%) |
| ◐ | 背景の色(白 → セピア → 黒) |
| 下の帯 | 今の章・読んだ割合。つまみを動かすと移る |
| PDF に保存 | 紙の大きさ・文字の大きさ・余白を選んで、Chrome の印刷画面を開きます。送信先で「PDF に保存」を選んでください |
| ⋮ | ファイルを開く・元のファイルを保存・背景の色・詳細設定 |

- 読んだ位置は本ごとに覚えて(300 冊まで)、次に開いたときにそこから表示します。文字の大きさ・背景の色・見開きも覚えます。
- リーダーで PDF・コミックを選ぶと、製本ビューアの画面に切り替えて開きます。
- 「PDF に保存」は、本の各章を紙の大きさに並べ直して印刷します(画像にはしないので、文字を検索・選択できます)。
  章ごとに新しいページから始めます(外すこともできます)。固定レイアウトの本は、1 ページずつ紙の大きさに縮めて並べます。

**表示できないもの**: KFX(Amazon の独自形式)と、DRM(コピー防止)のかかった本(Kindle ストアの本、Adobe DRM の EPUB など)は、
開くと理由を表示します。購入したストアのアプリでお読みください。

### 6.17 PDF をほかの形式に変換して保存(0.4)

⋮ メニュー →「**ほかの形式に変換して保存…**」で、表示している PDF を、表示している順(削除したページは除く)に変換します。
元の PDF のファイルは変えません。保存先を選ぶ画面が出ます。

| 形式 | 中身 | ファイル名 |
|---|---|---|
| 画像(ZIP) | ページごとに 1 枚の画像(`001.png`、スキャンのページは `001.jpg`) | `元の名前_画像.zip` |
| コミック(CBZ) | 画像 + ComicInfo.xml(右綴じなら漫画の向き)。コミックのリーダーで読めます | `元の名前.cbz` |
| EPUB(固定レイアウト) | ページごとに 1 枚の画像。PDF のしおりが目次になります。右綴じならページが右から左へ進みます | `元の名前.epub` |
| テキスト(.txt) | PDF の文字(OCR の文字を含む)。ページの区切りに「［12ページ］」を入れられます。BOM 付き UTF-8 | `元の名前.txt` |

- **画像**: スキャンのページ(1 枚の JPEG だけのページ)は、元の JPEG をそのまま使います(画質は元のまま)。
  文字・図のページは、選んだ解像度(150〜600 dpi)で描き、PNG(劣化なし)か JPEG(小さい)にします。
- **読む向き**: CBZ・EPUB の読む向きは、ツールバーの綴じ方向に従います。
- **Kindle の形式(MOBI・AZW3・KFX)には変換できません**。Kindle で読むときは、EPUB を Amazon の「Send to Kindle」で送ってください
  (固定レイアウトの EPUB は受け付けられないことがあります)。
- 文字の入っていない PDF(OCR していないスキャン)は、テキストにできません(そのことを画面に出します)。

## 7. 強制ダウンロード対策(第1層・第2層・第3層)

サイトが「表示せずにダウンロード」させようとしている PDF も、ビューアで開きます。
**PDF だと判断できるものだけ**を対象にし、それ以外には一切触れません。

| サイト側の状態 | 動き |
|---|---|
| ① `Content-Disposition: attachment`(保存させる指示)付きの PDF | ビューアで開きます(第1層: 応答の書き換え) |
| ② `application/octet-stream` などで配信され、URL が `.pdf` で終わる | ビューアで開きます(第1層) |
| ②' `octet-stream` などで、ファイル名(Content-Disposition)が `.pdf` | ビューアで開きます(第1層) |
| ③ PDF へのリンクに `download` 属性(保存専用の指定)が付いている | 新しいタブのビューアで開きます(第2層)。**Alt キーを押しながらクリック**すると、従来どおり保存します |
| ④ `blob:` の URL や、ページのスクリプトによる保存 | 保存が終わったあと、保存されたファイルをビューアで開きます(第3層) |
| `octet-stream` で、URL にもファイル名にも `.pdf` が無い | 第1層・第2層は触りません。保存後、第3層がファイルの先頭を読んで PDF なら開きます |
| ⑤ 一度しか使えない URL | 1回目は開けません(下記)。案内の画面から「このサイトは自動で切り替えない」を押すと、次からは開けます |
| URL は `.pdf` でも中身が HTML / PDF ではないダウンロード | 触りません |
| POST(フォーム送信)の応答として返る PDF | 自動切り替えしません(Chrome 標準で表示)。再取得するとフォームの送信をやり直すことになるためです |

### 第3層について

- 保存されたファイルを開くため、「**ファイルの URL へのアクセスを許可する**」がオンである必要があります。
  オフのときは、許可の手順と「このファイルを選んで開く」「保存されたフォルダを開く」の案内を出します。
- 元のファイルは、初期値では**残します**。詳細設定で「削除する」にすると、ビューアで読み込んだ後にファイルとダウンロード履歴を消します
  (この場合、ビューアを閉じると再表示できないので、残したいときはダウンロードボタンで保存してください)。
- 次のものは開きません: Alt+クリックで保存したもの、Chrome 標準ビューアや製本ビューアの保存ボタンで保存したもの、
  拡張機能が保存したもの、対策の対象外にしたサイト、起動方式が「ボタンを押したときのみ」のとき、対策がオフのとき。
- 注意: Chrome の右クリックメニューの「名前を付けてリンク先を保存」は、サイトによる保存と見分けがつかないため、
  保存後に製本ビューアが開きます(ファイルはそのまま保存されています)。

### 一度しか使えない URL(⑤)の動き

自動切り替えでは、まず元の URL にアクセスして PDF かどうかを確かめ、そのあと製本ビューアが同じ URL から PDF を取り直します。
一度しか使えない URL では、最初のアクセスで使い切ってしまうため、取り直せずに「PDFが見つかりませんでした(HTTP 410 など)」と表示されます。

- 画面の「**このサイトは自動で切り替えない**」を押すと、そのサイトを「自動切り替えしないサイト」に加えて元のページに戻ります。
- もう一度リンクを開くと、Chrome が PDF を直接受け取ります。保存させる PDF なら保存され、第3層が製本ビューアで開きます。
  表示する PDF なら Chrome 標準ビューアで表示されます。
- 保存された PDF は、「ファイルを開く」またはドラッグ&ドロップでいつでも製本ビューアで見られます。

## 8. 詳細設定

拡張機能のアイコンを右クリック →「オプション」、またはビューアの ⋮ メニュー →「詳細設定」で開きます。
変更はすぐに保存されます。

0.5 から、画面の入口は4つの分類です。分類を選ぶと、その分類の項目だけが出ます(左上の「← 詳細設定のトップ」で戻ります)。

| 分類 | 中の項目 |
|---|---|
| 1. 開く・読む | 起動(自動で開くか・切り替えないサイト・パソコン内の PDF)/ 表示(開いたときの表示・綴じ方向・表示位置・テーマ・回転ボタン)/ 電子書籍・コミック(読む向き・見開きの画像・パソコン内の本) |
| 2. スキャン・ページ操作 | スキャンの整え(見開きの分割・余白・本を読む向き・PDF の1ページ目・PDF ごとの設定)/ コピー・画像(コピーの方法・画像の画質と大きさ・ショートカット・補助プログラム)/ ページ収集(書き出し後・保存の上限) |
| 3. 印刷・製本出力 | 印刷の画質 / 製本用PDF出力(面付け・用紙・両面の綴じ方向・白紙の位置・大きさの基準・プレビュー)/ 付属・ファイル名(付属の出力・使い道・出力ファイル名・カバー・表紙・帯などの項目) |
| 4. 詳細管理・トラブル対応 | 強制ダウンロード対策 / データ管理(保存しているデータ・設定の書き出し・読み込み)/ 動作確認(速度ログ)/ この拡張について(使い方・ライセンス・すべて初期値に戻す) |

| 項目 | 初期値 | 他の選択肢 |
|---|---|---|
| 起動方式 | PDF を開くと自動で製本ビューアで開く | ボタンを押したときだけ |
| 自動切り替えしないサイト | なし | 1行に1サイト(サブドメインも対象) |
| パソコン内の PDF(file://) | 製本ビューアで開く | 開かない(Chrome 標準) |
| 開いたときの表示 | 製本表示 | 見開き / 単ページ |
| 綴じ方向 | 左綴じ | 右綴じ |
| 表示位置 | 前回見ていたページから表示する | 常に1ページ目から |
| 回転ボタン(0.5) | 左に 90° | 左・右 × 90°・180°・270°(ボタンの右クリックの「既定の設定を上書きする」でも変わる) |
| テーマ | システムに従う | ライト / ダーク |
| 印刷の画質 | **元の PDF で印刷**(元の PDF のまま Chrome の印刷機能で印刷。0.2 から。昔の名前は「最高画質」) | 画像として印刷・高画質(300dpi の画像)/ 画像として印刷・標準(150dpi の画像)/ 自動(50ページまでは高画質、それより多いときは標準) |
| スキャンした見開き(0.3) | 自動で1ページずつに分けて表示する | 分けるかどうか聞く(ツールバーにボタンを出す)/ 何もしない |
| スキャンの余白(0.3) | 除く(ページの大きさをそろえる) | 除かない(ノドの位置で左右に分けるだけ) |
| スキャンした本を読む向き(0.5) | ビューアの綴じ方向に合わせる | 右から左 / 左から右 |
| スキャンの PDF の1ページ目(0.5) | 本の最初のほうの見開き | 本の最後のほうの見開き(順を逆にする) |
| コミックの読む向き(0.4) | 本の情報に従う(無ければ右綴じ) | いつも右綴じ / いつも左綴じ |
| コミックの見開きの画像(0.4) | 2 ページに分ける | 分けない |
| パソコン内の電子書籍・コミック(0.4) | 製本ビューアで表示する | 表示しない(Chrome のまま。ダウンロードになります) |
| 強制ダウンロード対策 | オン | オフ |
| 対策の対象外にするサイト | なし | 1行に1サイト |
| 強制ダウンロード時の元ファイル | 残す | 削除 |
| コピー(1ページ) | 画像をクリップボードへ | PDF をファイル保存 / 画像をファイル保存 |
| コピー(複数ページ) | **PDF としてコピー**(ファイルとしてクリップボードへ。0.2 から) | 画像としてコピー / PDF をファイル保存 / 画像を ZIP で保存 |
| 画像としてコピー(複数ページ) | 1ページ1枚の画像ファイル | ZIP にまとめる |
| 画像にする画質 | **元データ優先**(元の画質。0.2 から「最高画質」の名で。0.7.0 から dpi を基本に) | 高画質(300dpi・0.6.8 までは長辺 2400)/ 標準(150dpi・0.6.8 までは長辺 1600)/ 指定する(dpi 100〜1200) |

| 白紙挿入位置 | 最後のページ(カバーの裏表紙)の直前 | 最初のページ(カバーの表紙)の直後 / 毎回指定する(任意のページの間、複数箇所可) |
| 面付け | あり | なし |
| 出力用紙サイズ | 元のページから自動 | A3 / A4 / A5 / B4 / B5 / レター / タブロイド / 元のページ2枚分(すべて横向き) |
| 両面の綴じ方向 | 短辺とじ | 長辺とじ |
| 大きさの基準 | 最も多い大きさに合わせる | 最初のページに合わせる / ページ指定(0.5。何ページ目かは出力の画面で選ぶ) |
| 出力ページのプレビュー(0.5) | 表示しない(サムネイル表示OFF) | 表示する |
| カバー・表紙・帯などの項目(0.5) | 決まった8項目(帯だけ複数可) | 項目の追加・削除、表示する・しない、複数可、並び |

詳細設定の画面には、ほかに「保存しているデータ」(ページ役割を保存している PDF の一覧と削除)、

「スキャンの整え」の欄では、PDF ごとに覚えている整え方の数を見たり、まとめて消したりできます。

## 9. 権限とその理由

| 権限 | 使う理由 |
|---|---|
| ストレージ(`storage`) | 設定と速度ログを、この拡張機能の中に保存するため |
| 大容量の保存(`unlimitedStorage`) | ページ収集で、元の PDF を拡張機能の中のデータベースに保存するため(Chrome に自動で消されないように) |
| ダウンロードの表示(`downloads.ui`)**0.4.1** | 補助プログラムが無いときの「コピー」の保存中に、ダウンロードの表示(ツールバーの印・吹き出し)を出さないため |
| ダウンロード(`downloads`) | コピー・収集の書き出しで作ったファイルを保存するため(同じ名前があるときは連番を付けて上書きしない)。強制ダウンロード対策の第3層で、保存された PDF を見つけて開くためにも使います |
| クリップボード書き込み(`clipboardWrite`) | コピーで、ページの画像や、保存したファイルの場所・元のリンクをクリップボードに入れるため(読み取りはしません) |
| 補助ページ(`offscreen`) | 第3層で、種類の分からないダウンロードの先頭を読み、PDF かどうかを確かめるため(画面には出ません) |
| 通信の書き換え(`declarativeNetRequestWithHostAccess`) | PDF を開いたときに製本ビューアへ切り替えるため。強制ダウンロード対策(保存させる指示を外す)、「Chrome標準で開く」の1回だけの除外、ビューアが PDF を取り直すときのリファラ引き継ぎにも使います |
| 全サイトへのアクセス(`<all_urls>`) | どのサイトの PDF でも扱えるようにするため(通信の書き換え、download 属性の無効化、ログイン状態のままの PDF 取得) |
| ページ遷移の検知(`webNavigation`) | ファイルアクセスが未許可のときに案内を出す、「その1回だけ」の除外を読み込み完了で解除する、PDF を表示中のタブを見分けるため |
| 通信の観察(`webRequest`) | **読み取り専用**です。PDF を表示中のタブかどうか(右クリックメニューの表示用)と、元のページ遷移のリファラを知るために使います。通信を止めたり変えたりはしません |
| スクリプトの登録(`scripting`) | download 属性を無効にするスクリプトを、対象外サイトの設定に合わせて登録するため。アイコンを押したタブが PDF かどうかの確認にも使います |
| 右クリックメニュー(`contextMenus`) | 「製本ビューアで開く」「リンク先のPDFを製本ビューアで開く」などを Chrome のメニューに出すため |
| ネイティブ アプリとの通信(`nativeMessaging`)**任意の権限・0.2** | 補助プログラム(6.14)に、コピーするファイルを渡すため。**詳細設定で「補助プログラムを使えるようにする…」を押したときだけ**求めます(使わなければ求めません。「使うのをやめる」で外せます)。補助プログラム以外のアプリとは通信しません |

- 0.3 の「スキャンの整え」は、新しい権限を使いません。画像を調べる処理も含めて、すべてこの拡張機能の中で行います。
- 0.4 の「電子書籍・コミック」も、新しい権限を使いません。パソコン内の本(`file://`)を開いたときの切り替えに「ページ遷移の検知」を、
  本へのリンクの右クリックメニューに「右クリックメニュー」を使います。本の読み込み・変換は、すべてこの拡張機能の中で行います
  (本のファイルを外部に送ることはありません。リーダーとビューアの間のファイルの受け渡しも、この拡張機能の中のデータベースを使い、1 日で消します)。
- **プライバシー**: 外部サーバーへの送信・解析・広告・更新確認は一切行いません。
  通信するのは、あなたが開いた PDF を元のサイトから取得するときだけです。
  収集したページと元の PDF は、この拡張機能の中(あなたのパソコンの Chrome のプロファイル)にだけ保存されます。
  PDF 内の JavaScript は実行しません。

## 10. 実装側で決めたこと(仕様書に書かれていない細部)

### フェーズ1

1. **テーマ**: Chrome 標準ビューアは常に暗い配色ですが、仕様(システムのライト/ダークに追従)を優先し、
   初期値は「システムに従う」にしました。ダークのときは Chrome 標準とほぼ同じ配色、ライトのときは同じ配置の明るい配色です。
   Chrome 標準とまったく同じ見た目にしたい場合は、詳細設定でテーマを「ダーク」にしてください。
2. **最初の表示**: 製本表示、倍率は「自動」(画面の幅に合わせ、大きくなりすぎない倍率)で開きます。
3. **サイドバーは閉じた状態で開きます**。サムネイルの準備で最初のページの表示を遅らせないためです(仕様 4.3)。☰ で開きます。
4. **表示位置の復元**: 同じ PDF を再び開くと、前回見ていたページから表示します。倍率と回転は復元しません
   (開いたら回転していた、という戸惑いを避けるため)。設定でオフにできます。
5. **download 属性付きのリンク**は、同じタブではなく**新しいタブ**のビューアで開きます。サイトが「今のページから離れない」ことを
   前提にしている場合が多いためです。Alt+クリックで従来どおり保存できます。
6. **POST の応答として返る PDF** は自動切り替えの対象外です(再取得するとフォーム送信をやり直してしまうため)。
   Chrome 標準ビューアで表示されます。
7. **PDF の取得に失敗したとき**は、自動で Chrome 標準に切り替えるのではなく、理由と「Chrome標準で開く」ボタンを表示します
   (仕様で選べる2案のうち後者)。自動で切り替えると、使い捨ての URL を使い切ったり、ダウンロードが始まったりするおそれがあるためです。
8. **ログインが必要なサイト**: ビューアは PDF を、そのサイトの Cookie を付けて取得します。元のページ遷移にリファラ(参照元)が
   あれば、それも付けて取得します(リファラを確認するサイト向け)。
9. **Chrome の右クリックメニュー**: ページの「製本ビューアで開く」は、Chrome 標準ビューアで PDF を表示しているタブでだけ出します
   (関係のないページのメニューを増やさないため)。
10. **拡張機能のアイコン**: PDF を表示中のタブでは「製本ビューアで開く」、それ以外のページでは空のビューアを開きます。
11. **PDF 内の JavaScript は実行しません**(安全と速度のため)。フォームの自動計算など、スクリプトに頼る動きは働きません。
    必要な場合は「Chrome標準で開く」を使ってください。
12. **PDF.js は legacy(互換)ビルド**を使っています。通常版は新しい JavaScript 機能を使っており、Chrome 128〜141 などで動かないためです。
    バージョンは 6.4.299 に固定しています。
13. **拡張機能の ID を固定**しています(`manifest.json` の `key`)。フォルダを差し替えても設定が引き継がれます。
14. **消しゴム**は、なぞった注釈(線)を1本ずつ丸ごと消します(「元に戻す」で戻せます)。線の一部だけを消すことはできません。
15. **描画の範囲**: 表示中のページと前後のページだけを描画し、描画結果はメモリ上限(約512MB)の範囲で保持して、
    離れたページから破棄します。大きな画像のページは、画面に必要な解像度までで描画します。
16. **注釈・印刷・フォームのコードの後読み**(仕様 4.3): PDF.js 公式ビューアはこれらの処理を1つのファイルにまとめて配布しているため、
    ファイル単位で後から読み込むことはできません(分割するには PDF.js を作り直す必要があり、更新が難しくなります)。
    代わりに、注釈ツールのパネルは押したときに作る、印刷は押したときにだけ準備する、PDF 内の JavaScript を動かす部品は同梱しない、
    という形で、最初のページの表示を妨げないようにしています。
17. **見た目の合わせ先**: Chromium 141 の標準 PDF ビューアの画面と、Chromium のソースコード(`chrome/browser/resources/pdf`)の
    配色・寸法・アイコンに合わせました。

### フェーズ2

18. **PDF の抜き出し**には、同梱の PDF.js が持つページ抽出機能を使います。元のテキスト・図形・画像をそのまま写し、
    再エンコードしません。暗号化された PDF、文書内のリンクとしおり、フォームにも対応し、複数の PDF をまとめるときは
    同じフォントや画像を1つにまとめます。まれに PDF.js で抜き出せない文書は pdf-lib で抜き出します。
    pdf-lib は、フェーズ3の製本用 PDF(白紙挿入・面付け)でも使います。
19. **暗号化された PDF からの抜き出し**: 1つの PDF だけから抜き出したファイルは、元の PDF と同じ保護(パスワードなど)を引き継ぎます。
    元の PDF を開くのにパスワードが必要だった場合は、書き出した PDF もそのパスワードで開きます。
20. **コピー(0.1 までの名前は AI用コピー)の画像**は、画面に見えているとおり(回転、書き込んだ注釈、フォームの入力内容を含む)に作ります。
    0.1 までの初期値は長辺 2400 ピクセルでした(0.2 からは「最高画質」= 元の画質。上の 57)。
21. **コピーのショートカット**は Ctrl+Shift+C にしました(Ctrl+C の「コピー」に Shift を足した形)。
    Chrome では開発者ツールの「要素の検証」と同じ組み合わせですが、製本ビューアの画面の中でだけ、ページのコピーになります。
    詳細設定で変えられます(Chrome やビューアが使っている組み合わせは登録できません)。
    押したときは、マウスの下のページ(サムネイルを複数選んでいるときは選んだページ)を対象にします。
22. **右クリックメニュー**は製本ビューア独自のものにし、Shift+右クリックで Chrome の通常のメニューを出せるようにしました。
    フォームの入力欄の上では、貼り付けなどのため通常のメニューを出します。
23. **サムネイルの複数選択**は、ファイル操作と同じ Ctrl+クリック(1つずつ)・Shift+クリック(範囲)にしました。
    普通のクリックは今までどおりそのページへ移動します。
24. **収集の重複**: 同じ PDF の同じページは、重ねて収集しません(「すでに収集済み」と知らせます)。
25. **収集に保存する PDF**: 元の PDF をそのまま保存します(ビューアで書き込んだ注釈は含めません)。ただし、開くのにパスワードが必要な PDF は、
    書き出しのたびにパスワードを聞かずに済むよう、パスワード無しの写しを保存します(写しは拡張機能の中にだけ保存されます)。
26. **収集の保存上限**は 1GB にしました。上限を超える追加は、確認のうえで追加できます(止めずに知らせる)。
27. **複数の PDF をまたぐ書き出しのファイル名**は、最初のページの元ファイル名に「ほか」を付けます(`元ファイル名ほか_抜粋_日時.pdf`)。
    日時は `20261006_2130` の形です。
28. **保存先**は Chrome のダウンロード先のフォルダです(Chrome の「保存する前に各ファイルの保存場所を確認する」の設定に従います)。
    日本語のファイル名を扱えない環境(文字コードが UTF-8 でない Linux など)では、英数字の名前(`_抜粋_` → `_excerpt_`)で保存します。
29. **第3層が動く条件**: 起動方式が「自動」で、強制ダウンロード対策がオンのときだけ動きます。種類の分からないダウンロードの中身の確認は、
    300MB までのファイルに限ります(大きなファイルの読み込みでパソコンを重くしないため)。
30. **使い捨て URL**: 第1層の仕組み上、1回目は使い切ってしまうため、エラー画面に「このサイトは自動で切り替えない」ボタンを置き、
    2回目から開けるようにしました(第6章の「既知の限界」の範囲)。

### フェーズ3

31. **本文**は「役割の付いていないページ」です。表紙・裏表紙の役割が無いときは、役割の無い最初のページを表紙、
    最後のページを裏表紙として扱います(「(自動)」と表示)。表紙・裏表紙の候補のうち、選ばなかったページは出力しません。
32. **帯の運用の仮定**: 帯・帯表紙・帯裏表紙の役割のページは、初期値では本体に入れず、元の順番で帯の PDF に入れます。
    運用が違う場合のため、役割ごとの使い道(帯として出力 / 表紙の候補 / 裏表紙の候補 / 出力しない)を、
    出力の画面と詳細設定で変えられるようにしました(フェーズ4。仕様 16章)。表紙・裏表紙の役割の使い道は変えられません。
33. **白紙の位置の指定**は「何ページ目の後ろ」を元の PDF のページ番号で書きます(`5, 12`、`5x2` は5ページ目の後ろに2枚)。
    必要な枚数より少ない指定は、残りを裏表紙の直前に入れます。
34. **用紙の自動選択**: 元のページ2枚分が 3% 以内の縮小で収まる、いちばん小さい定形の用紙(A3・A4・A5・B4・B5・レター・タブロイド)を選びます。
    どの用紙でも 15% 以上の拡大になる小さなページは「元のページ2枚分」の大きさにします。
35. **長辺とじ**を選ぶと、裏面全体を180度回して作ります。PDF には両面の設定(短辺とじ/長辺とじ)と「実際のサイズで印刷」の
    目安も書き込みます(対応している印刷画面では初期値になります)。
36. **面付けした PDF** では、注釈は「印刷される見た目」をページに描き込んでから配置し、リンクは外します(印刷用のため)。
    面付けしない PDF では、リンクやしおりも残ります。
37. **書き込み・フォームの入力内容**は出力に含めます(コピーの PDF 保存も同じ)。ただし、パスワードを入力して開いた PDF では、
    書き込みを反映した写しにもパスワードが必要になるため、新しく書き込んだ注釈だけを含め、フォームの入力内容は含めません。
38. 出力する PDF は、元の PDF が暗号化(パスワードや印刷制限)されていても暗号化しません。
39. 面付けするときは、面付けした PDF だけを出力します(読む順の PDF も欲しい場合は、面付けを外してもう一度出力してください)。

### フェーズ4

40. **設定の書き出しの形式**: JSON(人が読める形)で、詳細設定のすべての項目と、PDF ごとのページ役割(PDF の指紋・名前・ページ数・
    ページ番号ごとの役割)を書きます。収集したページと元の PDF は大きくなるため入れません。速度ログも入れません。
41. **読み込みのしかた**: 設定は「ファイルにある項目だけ置き換える」、ページ役割は「同じ PDF だけ置き換え、ほかは残す」にしました。
    今の設定やほかの PDF の役割を、読み込みで思いがけず消さないためです。全部を入れ替えたい場合は、先に「すべて初期値に戻す」
    「ページ役割をすべて消す」を押してから読み込んでください。
42. **帯の役割の使い道**の初期値は、0.0.3 と同じ「帯として出力」です(初期値のままなら出力は 0.0.3 と変わりません)。
    出力の画面では、その PDF にある帯の役割の分だけ選ぶ欄が出ます。
43. **ペンの線**: PDF.js は続けて描いた線を1つの注釈にまとめますが、製本ビューアでは1本描くごとに確定させ、1本ずつの注釈にしました。
    消しゴムと「元に戻す」が1本ずつ効き、Chrome 標準ビューアの使い心地に近くなります。
44. **見開きのページ番号**: PDF.js は見開きで「同じだけ見えているページ」のうち番号の小さい方を現在のページにするため、
    見開きの右のページへ移動すると番号が1つ前に戻って見えました。同じだけ見えているときは移動した先のページを優先するようにしました。
    スクロールで見開きが移ると、これまでどおり見えているページの番号に変わります。
45. **詳細設定の並び**: 仕様の第12章の順(起動 → 表示 → コピー・画像 → 収集 → 製本用PDF出力 → 強制ダウンロード対策 → 速度ログ)に並べ、
    データの管理と書き出し・読み込みを最後にまとめました。

### 0.1

46. **ページの削除の仕組み**: 同梱の PDF.js 6.4.299 が持つ「ページの整理」の機能(表示上のページと元のページの対応表)を使います。
    PDF のデータを作り直さないので、大きな PDF でもすぐに消え、「元に戻す」も速くできます。
    元の PDF のデータは変わらないため、ページ役割・収集は元の PDF のページ番号で記録し、表示上のページ番号と対応させています。
47. **PDF.js の不具合への対処**(PDF.js の配布物は変えず、製本ビューア側で補っています):
    - 削除したページの書き込みが別のページに移る → 削除の前に、そのページの書き込みを消す(確認を出す)
    - 削除を確定するとき、ページ番号を取り違えて別のページの書き込みを消す → その処理を止める
    - 削除を元に戻したページに書き込めない / 書き込みの「元に戻す」で、削除したページの書き込みが別のページに出る → 登録し直す・消す
    - 削除を元に戻したとき、PDF.js の「ページ番号 → ページ」の控えが別のページのままになり、印刷・検索などが別のページの中身を使う → 控えを並びに合わせ直す
    - ページを組み替えると見開きの枠が外れる → 見開きを組み直す
48. **ページの並べ替え**(サムネイルのドラッグ)は使えないようにしています。PDF.js の並べ替えは「元に戻す」ができず、
    クリックのつもりで少し動かしただけで並びが変わってしまうためです。
49. **ページの削除は、全部のページの読み込みが終わってから**できます(PDF.js が対応表を正しく保てるのは、全部のページを読み込んだ後のため)。
    読み込み中に押すと、待つように知らせます。
50. **保存の名前**: 元の名前に `_編集済み` を付けた名前を候補にします(そのまま保存しても、元のファイルを上書きしにくくするため)。
    保存先を選ぶ画面は、0.4.2 から Chrome の「名前を付けて保存」の画面(File System Access)です。ダウンロードの一覧には残りません(0.4.1 まではダウンロードの仕組みで出していました)。
51. **保存した後**も、ビューアは元の PDF を表示したままです(保存した PDF に開き直しません)。続けて編集して、もう一度保存できます。
52. **ページラベル**(PDF に「i, ii, 1, 2…」のような番号が付いているもの)は、ページを削除すると合わなくなるため、
    削除している間はページ番号で表示します(元に戻すと戻ります)。
53. **閉じる前の確認**は、ブラウザの決まりで、タブの × で閉じる・再読み込みのときは Chrome の決まった確認画面になります。
    製本ビューアの中で文書を閉じる操作(⋮ →「PDFを閉じる」、別の PDF を開く、Chrome標準で開く)のときは、「保存しますか?」の画面を出します。
    「PDFを閉じる」で「保存しない」を選んだときは、Chrome の確認を重ねて出さずにタブを閉じます。
54. **右綴じの矢印キー**: 右綴じのときだけ ← と → を入れ替えます(見開き・単ページのどちらでも)。拡大して横にスクロールできるときは、
    矢印キーは今までどおり横にスクロールします(ページは「ページに合わせる」のときだけめくります。PDF.js と同じ)。
55. **右綴じの見開きの並べ方**: 以前は文字の向き(右から左)で左右を入れ替えていたため、見開きが画面より広いと左側にはみ出して見られませんでした。
    並びの順番で入れ替える方法に変え、はみ出す分は右側に出して横にスクロールできるようにしました。
56. **印刷の画質の「自動」**: 50ページまでは 300dpi、それより多いときは 150dpi にします。300dpi は文字がくっきりしますが、
    印刷の準備にメモリと時間を使うため、ページ数の多い PDF で印刷が止まらないようにしています。

### 0.2

57. **「最高画質」の意味**: 「元の画質と同じ、またはそれを目指してできる最大限」を、次のように決めました。
    - 画像: スキャンしたページは、PDF の中の画像の解像度(ページに対する画素の細かさ)をそのまま使います。文字・図(ベクター)は解像度に上限が無いため、
      印刷の品質の目安の 600dpi にしました。両方あるページは、細かい方に合わせます。OCR の見えない文字は、見える文字としては数えません。
    - ファイルに保存するときは、ページが1枚の JPEG 画像だけでできていれば、その JPEG をそのまま取り出します(デコードして作り直すと、
      わずかに変わるため)。ページの回転・書き込み・切り抜き(画像がページからはみ出す)・CMYK などのときは、PNG に描きます。
    - クリップボードには画像を PNG でしか入れられないため、コピーは元の解像度の PNG です。
    - 1枚の画像は 6400 万画素まで(それより大きいと、Chrome がメモリ不足で失敗するため)。
58. **最高画質の印刷のしかた**: 画面に見えない小さな枠に PDF を読み込み、Chrome の PDF 表示機能の印刷を使います(PDF.js の印刷は、
    ページを画像にするしかないため)。編集していれば、編集を反映した PDF を作って印刷します。パスワード付きの PDF は、パスワードを外した写しを印刷します
    (パスワード付きの PDF を編集しているときは、画像にして印刷します)。題名の無い PDF には、印刷用の写しにだけファイル名を題名として付けます
    (「PDF に保存」のファイル名の候補が英数字の羅列にならないように。元の PDF は変えません)。
59. **ファイルのコピーのしかた**: クリップボードにファイルを入れるには、OS の機能を使う補助プログラムが必要です。補助プログラムは、
    Windows は追加のインストールが要らない PowerShell、Mac は最初から入っている osascript(JavaScript)、Linux は Python 3 で作りました。
    補助プログラムを使う権限は「任意の権限」にして、使うと決めたときだけ求めます。
    補助プログラムには、データを 1MB ずつ渡します(Windows PowerShell 5.1 は 2MB を超えるデータを一度に読めないため)。
60. **コピーしたファイルの置き場所**(0.4.1 で変更): 補助プログラムがあるときは、見えない一時フォルダの中の、製本ビューア専用のフォルダ
    (`seihon-viewer-copy`)です。ご依頼どおりコピーは使い捨てで、次にコピーするとき、このフォルダの中だけを片付けます(ほかの場所は消しません)。
    クリップボードはファイルの場所を指すだけなので、次にコピーするまでは貼り付けられます。補助プログラムが無いときは、Chrome のダウンロードでしか
    ファイルを作れないため「ダウンロード」の「製本ビューア_コピー」に保存し、次にコピーするときに、製本ビューアが保存した前のファイルを消します。
61. **「画像としてコピー」で複数ページのとき**: 1ページ1枚の画像ファイルにしました(チャット欄などにそのまま貼り付けられるため)。
    ZIP にまとめたいときは、詳細設定で切り替えられます。1ページのときは、どこにでも貼り付けられる「画像そのもの」をクリップボードに入れます。
62. **複数ページのコピーの初期値**を「PDF としてコピー」にしました(名前が「コピー」になったため。0.1 までは PDF をファイルに保存)。
    補助プログラムが無いときも、PDF を保存して場所をクリップボードに入れるので、0.1 までと同じように使えます。
63. **「ページに合わせる」で選ぶページ**: 画面に見えている面積がいちばん大きいページです(見開きの表示では見開きごとに合計します)。
    同じくらいなら、今のページを優先します。倍率は、そのページ(見開き)がちょうど収まる大きさにします(0.1 では、いちばん大きな見開きに合わせていました)。
    「幅に合わせる」は 0.1 と同じく、いちばん幅の広い見開きに合わせます。表示モードを切り替えたときに「ページに合わせる」の状態なら、同じように合わせ直します。
64. **表示モードのボタンの順番**: ご指定どおり 単ページ → 製本表示 → 見開き → 単ページ です。アイコンは今の表示モードを表し、
    マウスを置くと、次に何になるかを表示します。切り替えたときは、画面の下に短く表示モードの名前を出します。
65. **役割の名前の変更**は、名前だけを変え、保存してある役割(中身)は変えていません。0.1 の「表紙」を付けたページは「カバーの表紙」になり、
    製本用PDF出力での扱い(本の最初のページ)も同じです。帯表紙・帯裏表紙だったページは「表紙」「裏表紙」になり、付属として出力されます。
    新しい役割(折り返し・しおり)も付属です。付属の PDF の中は、元のページの順に並べます。
66. **付属の出力ファイル名**: 帯だけでなく表紙・折り返し・しおりも入るため、`_帯` から `_付属` に変えました(0.1 で `_帯` のままだった場合は、更新で `_付属` になります)。
67. **元の場所のボタン**: 「ファイルを開く」・ドラッグ&ドロップで開いたファイルは、ブラウザの決まりで場所(フォルダ)が分からないため、ファイル名だけコピーできます。

### 0.3

68. **スキャンかどうかの判断**: ページが横長(幅が高さの 1.15 倍以上)で、最初の4ページの多くが「画像1枚だけ」でできている
    (OCR の見えない文字はあってよい)PDF を、スキャンとみなして調べます。文字・図でできた PDF(スライドなど)では何もしません。
69. **見開きと冊子の紙の見分け**: ノドは「上から下まで続く、まわりより暗い縦の線・影」として、ページの幅の 30〜70% の範囲で探します
    (列ごとに「左右より暗い度合い」の中央値を見るので、文字の並びには反応しません)。調べたページの 60% 以上にノドがあれば
    「本・ノートの見開き」、無くて真ん中に何も書かれていない縦の帯があれば「2ページ分が並んだ平らな紙(ばらした冊子など)」とします。
70. **自動で行うのは見開きの分割だけ**: 冊子の並べ替えは、並べ方を間違えると分かりにくいため、ボタンを押してからにしました
    (一度選べば、その PDF は次から自動で並べ替えます)。
71. **分ける位置**: 見開きは、ページごとに見つけたノドの位置です(紙の真ん中とは限りません)。ノドの線・影(線の太さ + 1mm)は、どちらのページにも入れません。
    平らな紙は紙の真ん中です(どのページでも何も無い帯が真ん中から外れているときだけ、その帯の中で分けます)。
72. **余白の除き方**: ページの中身(ある程度濃い画素のまとまり)の範囲を調べます。紙の端に触れているもの(ふたの影)、縁の近くの長い直線(本の縁・影)、
    小さな点(ごみ)、縁の近くの小さなもの(綴じ穴の影)、薄い灰色だけのもの(ノートの罫線のかけら・裏写り)は中身に数えません
    (表の罫線など、中身の範囲の中の線は中身に数えます)。中身の周りに 6mm の余白を残します。
73. **ページの大きさと位置のそろえ方**: 全部のページを同じ大きさにします。横は、ノドからの距離でそろえます(本の綴じ目からの文字の位置は、どのページも同じため)。
    縦は、本のように上下いっぱいの中身(見出し・ページ番号)がほとんどの見開きにあるときは、見開きごとに中身に合わせます(手で置いたときの上下のずれも直ります)。
    ノートのように中身の量がまちまちなときは、どのページも同じ位置で切ります(中身に合わせると、書き込みの量でページが上下にずれて見えるため)。
    そろえた範囲に本の縁などがかかるページは、その部分を白く覆います(画像は変えずに、上に白い四角を重ねます)。
74. **元の画質のままにする作り方**: 元のページの中身(画像を描く命令)をそのまま使い、表示する範囲を変えた新しいページを作ります。
    1枚の画像を2ページで共有するので、ファイルの大きさはほとんど変わりません。ページの左下が (0, 0) になるように中身をずらすので
    (ページの大きさの指定は [0 0 幅 高さ])、ほかのソフトや印刷でも同じ範囲が出ます。元の PDF の目次(しおり)・ページ番号の付け方・タグ・フォーム・注釈は、
    ページの組み立てが変わるため、整えた PDF には入れません。
75. **OCR の文字の振り分け**: ページの中身を読んで、文字を描く命令の書き始めの位置が、そのページの範囲の外にあるものを取り除きます。
    読めない書き方のときは取り除きません(そのときは、検索でもう片方のページの文字も見つかることがあります)。
76. **調べる速さ**: スキャンの JPEG は、ブラウザの機能で 1/2〜1/8 の大きさに縮めて直接読み込みます(元の大きさで読むより何倍も速い)。
    調べる処理は Worker(画面とは別の処理)で行うので、調べている間もスクロールなどは重くなりません。
    JPEG でないスキャン(白黒の CCITT・JBIG2 など)は、ページを描いてから調べます(少し時間がかかります)。400MB を超える PDF は、開いたときには調べません。
77. **整え方を覚える**: 元の PDF の内容の指紋ごとに、最後に選んだ整え方を 300 件まで覚えます(古いものから消します)。
    開いたときの自動の分割は覚えません(詳細設定を「聞く」に変えたら、次からそのとおりになるように)。
78. **整えた PDF の指紋と ID**: 同じ元の PDF・同じ整え方なら同じになるようにしました(ページ役割などを、次に開いたときも使えるように)。
79. **表示モード**: 見開きを分けたときは、元のスキャンと同じ組み合わせで並ぶ「見開き」で表示します(製本表示では1ページ目が表紙として単独になり、
    組み合わせが1つずれるため)。元に戻したり、ほかの PDF を開いたりすると、元の表示モードに戻ります(自分で変えていたときは、そのまま)。冊子は製本表示のままです。
80. **綴じ方向**: 見開きは、左綴じなら左のページ、右綴じなら右のページが先です。冊子は、綴じ方向で表紙が紙のどちら側にあるかが決まります。
    綴じ方向のボタンを押すと、整えて表示しているページを並べ直します。
81. **整えた PDF の名前**: `元の名前_分割.pdf`(冊子は `_並べ替え.pdf`)。整えて表示している間にほかの機能で作るファイルも、この名前をもとにします。
82. **編集との関係**: ページの削除や書き込みをしていて保存していないときは、整える前に保存するか聞きます(自動の整えは行わず、ボタンで知らせます)。
    整えた後の削除・書き込みは、整えた PDF に対して行い、「保存」で `元の名前_分割_編集済み.pdf` として保存できます。

### 0.4

83. **表示のしかたの分け方**: 開くファイルの先頭を読んで種類を見分けます(拡張子が違っていても中身で判断します)。
    コミック(CBZ・CBR・CB7)と「どのページも画像 1 枚だけ」の EPUB は PDF にして製本ビューアで、それ以外の EPUB・MOBI・AZW・AZW3・FB2 は電子書籍リーダーで表示します。
    画像だけの EPUB を PDF にするのは、製本表示・印刷・PDF としての保存がそのまま使え、画質も変わらないためです。
84. **見分けの手がかり**: EPUB は ZIP の先頭の `mimetype`(または `META-INF/container.xml`)、MOBI・AZW・AZW3 はファイルの 60 バイト目の `BOOKMOBI`、
    KFX は先頭の `CONT`(または `DRMION`)、RAR は `Rar!`、7z は先頭の 6 バイトです。PDF として開けなかった URL(拡張子の無いダウンロードなど)も、中身を見て電子書籍なら開きます。
85. **DRM の見分け**: MOBI・AZW・AZW3 は最初のレコードの暗号化の欄、EPUB は `META-INF/rights.xml` と、フォント以外の暗号化(`encryption.xml`)で見分けます。
    フォントの難読化(IDPF・Adobe の方式)は DRM ではないので、そのまま表示します。
86. **コミックの PDF の作り方**: pdf-lib で、画像 1 枚を 1 ページにします。ページの大きさは、縦長の画像の高さの中央値が B6(182mm)になるように決めます
    (全部のページを同じ比率で縮めるので、見開きの画像は幅が 2 倍のまま)。JPEG の向き(EXIF)は、ページの回転で直します(画像は作り直さない)。
    作る処理は Worker(画面とは別の処理)で行い、作っている間も画面は固まりません。同じファイルからは同じ PDF ができるので(作った日時を入れない)、
    ページ役割・読んだ位置も次に開いたときに使えます。
87. **見開きの画像を分ける条件**: ほとんど(60% 以上)が縦長の本で、幅が高さの 1.2 倍を超える画像(1 枚目の表紙を除く)を見開きとみなします。
88. **電子書籍リーダー**: 表示には foliate-js を使い、画面(ツールバー・目次・検索・PDF に保存)は製本ビューアに合わせて作りました。
    本の章は iframe の中に表示します。本の中のスクリプトは、拡張機能のページの決まり(CSP: 拡張機能の中のスクリプトだけ実行できる)で止まり、
    念のため読み込む前にも `<script>`・`on…` 属性・`javascript:` のリンクを取り除きます。本の外へのリンクは新しいタブで開きます。
89. **縦書きの本の表示**: foliate-js は縦書きの本を「画面いっぱいの 1 ページ」で表示します(縦書きを 2 段に分けると行の途中で切れるため、見開きのボタンは横書きの本だけに効きます)。
90. **読んだ位置の記憶**: ファイルの先頭 1MB・末尾 64KB・大きさから作った指紋ごとに、位置(EPUB CFI)を 300 冊まで覚えます(古いものから消します)。
91. **PDF に保存(リーダー)**: 本の各章の本文と、本のスタイル(CSS)を 1 つの文書にまとめ、紙の大きさ・余白(`@page`)と文字の大きさを足して、
    見えない iframe で Chrome の印刷画面を開きます。Chrome の機能で PDF にするので、文字は文字のまま(検索・選択できる)です。
    直接 PDF のファイルを作らないのは、文字の本を PDF にするには文字の組版(縦書き・ルビ・禁則)が必要で、それができるのはブラウザの印刷機能だけのためです。
92. **画面どうしの受け渡し**: ビューアで開いた文字の本をリーダーに、リーダーで開いた PDF・コミックをビューアに渡すときは、
    この拡張機能の中のデータベース(IndexedDB)に一時的に置き、URL の `?h=…` で受け取ります(再読み込みしても開けるよう、1 日残します。合計 1GB を超えたら古いものから消します)。
93. **PDF からの変換**: 画像は「コピー」の元データ優先(0.7.0 までの「最高画質」)と同じ方法で取り出します(スキャンのページは元の JPEG)。ZIP・CBZ は無圧縮(画像はもともと圧縮済みのため)、
    EPUB は EPUB 3 の固定レイアウト(1 ページ 1 枚の画像を SVG で包む、Kindle Comic Converter などと同じ形)です。
94. **CBR(RAR)の読み込み**: libarchive(BSD ライセンス)を WebAssembly にした libarchive.js を使います。RAR4・RAR5 とも読めます。
    RARLAB の unRAR は使っていません。書庫を開く処理は、画面とは別の Worker で動きます。

### 0.4.2

95. **名前を付けて保存**: `showSaveFilePicker`(File System Access)で保存先を選び、そのファイルに書き込みます。権限は増えません。
    書き込みは一時ファイルに書いてから置き換える方式(Chrome の仕組み)なので、途中で失敗しても元のファイルは壊れません。
    保存先を選ぶ画面は「ダウンロード」フォルダから始まり、2回目からは前に選んだフォルダから始まります。
    この画面を出せないとき(クリックから時間がたった・ほかの理由で使えない)は、お知らせのボタンを押してもらうか、予備としてダウンロードの仕組みで保存します。
96. **ファイル名が無視されたことの見分け方**: ダウンロードフォルダに保存したファイルの名前が GUID(`8桁-4桁-4桁-4桁-12桁`)の形で、
    指定した名前がその形でないときだけ「無視された」とみなします(ほかの拡張機能が名前やフォルダを変えた場合は、その拡張機能の設定に従ったものとして何もしません)。
    消すのは、製本ビューアがその直前に保存したファイルだけです。覚えた日時は `chrome.storage.local` の `downloadNameBrokenAt` です。
97. **名前の変更**: 保存していない変更の1つとして扱います(タブの名前の「* 」、閉じるときの確認、「保存」ボタン)。
    題名は pdf-lib で書き込み、XMP に題名があれば同じ値に書き換えます(読めない XMP は外します。古い題名が優先して表示されないように)。
    この書き込みでは PDF 全体を書き直しますが、ページの中身(画像・文字)は作り直さずにそのまま写します。
    「編集は含めない」保存(元の PDF・整えた PDF・コミックの PDF)には名前の変更も含めません。印刷(最高画質)と「Chrome標準で開く」には含めます。

### 0.5

98. **回転ボタン**: 設定 `rotateStep`(-90・-180・-270・90・180・270)。右クリックの吹き出しで「回転」を押したときだけ回転し、
    「既定の設定を上書きする」がオンのときだけ設定を変えます。Ctrl+[ ・ Ctrl+] は Chrome と同じ 90° のまま。
99. **⋮ メニューから外した項目**: 機能は残しています(Ctrl+O、回転・コピーのショートカット、タイトルの右の鎖のボタン、サイドバーの「選択」)。
    「PDFを閉じる」だけは代わりがありません(タブの × で閉じると、保存していない変更があれば Chrome の確認が出ます)。
100. **項目の設定**: `bindRoleItems`(`{id, show, multi}`。追加した項目は `custom1` などの id と `label`・`use` を持つ。最大 20 個、名前は 20 文字まで)。
     ページ役割の保存の形は変えていないので、追加した項目の役割も、ページ役割の書き出し・読み込みでそのまま移せます。
     項目を削除すると、その役割のページは次に PDF を開いたときに役割の無いページになります。
101. **プレビューを出さないとき**は、サムネイルを作りません(大きな PDF でも画面がすぐ開きます)。面付けの並びは、出力後の画面のプリンターの設定の案内で確かめられます。
102. **ノドの影(上下の端)**: 紙の上の端・下の端(高さの 7%)で列ごとの明るさの中央値を取り、幅の 35〜65% の中でいちばん暗い所を探します。
     紙より 35 以上暗く、幅 1.5〜25mm の影が上下とも(片方だけなら 60 以上暗い影が)見つかれば、ノドとします。
     ノドの線で見つけた位置と 6mm 以上ずれていれば、影の位置を使います(太い罫線を間違えたときのため)。
103. **ノドの影の幅**: ノドから外へ、本文の高さ(15〜85%)の列ごとの明るさの中央値が紙の明るさに戻るまでの距離。
     ページの内側の端は、影の幅(全ページの 4分の3 の位置の値)か、中身から 1mm の所の、ノドに近いほうにします。ページの大きさは変えず、外側の余白が増えます。
104. **スキャンの読む向き**: 整えたときに、ビューアの綴じ方向を読む向きに合わせます(設定は変えず、ほかの PDF を開くと設定の綴じ方向に戻ります)。
105. **ダークモードの選択欄**: 一覧が白地に選択欄と同じ白い文字で出ていたため、一覧の項目(option)の地と文字の色を、メニューと同じ色に指定しました。

## 11. 速度比較の結果(仕様 4.3)

「リンクを開いてから、最初のページが画面に表示されるまで」の時間を、Chrome 標準ビューアと比べました。

### 計測方法

- 環境: Chromium 141(Linux、画面は仮想ディスプレイ、GPU なし、CPU 2コア)。PDF は同じパソコン内のサーバーから配信
  (通信時間はほぼゼロ)。
- 時間の測り方: 画面を録画し、ページを表示する部分が表示し終わった時刻を、ナビゲーション開始からの秒数で測定(各4回の中央値)。
  Chrome 標準ビューアは最初からサムネイルの列を開くため、その列とツールバーは比べる範囲から除きました。
  製本ビューアは、元の URL にアクセス → 製本ビューアへ切り替え → PDF を取り直す、までをすべて含みます。
  製本ビューアの内部計測(速度ログ)とも 0.1 秒前後の差で一致しました。
- PDF は仕様の3種類を用意しました。

| PDF | 内容 | サイズ |
|---|---|---|
| 文書 | 320ページの文字中心の文書(しおり付き) | 2.6 MB |
| スキャン本 | 210ページ、全ページがスキャン画像(線形化なし) | 113 MB |
| 画像中心 | 24ページ、大きな写真が中心(線形化なし) | 18.1 MB |

### 結果

| PDF | Chrome 標準 | 製本ビューア |
|---|---|---|
| 文書(2.6 MB) | 1.31 秒 | **0.72 秒** |
| スキャン本(113 MB) | 3.29 秒 | **0.81 秒** |
| 画像中心(18.1 MB) | 1.79 秒 | **0.92 秒** |

(0.0.4 で計測。0.0.1・0.0.2 での計測も同じ傾向で、フェーズ2〜4の機能を加えても最初の表示は遅くなっていません。
計測用の PDF は 0.0.4 の計測のときに作り直したため、大きさが以前の表と少し違います)

この環境では、3種類とも製本ビューアの方が先に最初のページを表示しました。
製本ビューアは PDF 全体の取得を待たずに、取得できた部分から最初のページを描画するため、ファイルが大きいほど差が開きます。

### 注意点

- 計測環境の Chrome 標準ビューアは、PDF を開くたびにパソコン内のフォントをすべて調べる処理(Linux 版の動作)に時間がかかり、
  フォントの多い計測環境(335書体)では、どの PDF でも表示まで 6〜8 秒かかりました。これは計測環境に特有の現象と判断し、
  上の表は、フォントを一般的な数(36書体)に減らした条件で両方を測り直した結果です。
- Windows / Mac の実機、GPU あり、インターネット越しの取得では、数値が変わります。インターネット越しの場合、
  製本ビューアは切り替えのために PDF へ2回アクセスするので(1回目は応答ヘッダーを受け取った時点で打ち切ります)、通信の往復が1〜数回分(通常は0.1秒前後)増えます。
- お使いのパソコンでの時間は、詳細設定で「速度ログ」をオンにすると、PDF を開くたびにビューア右下に表示されます。
  同じ PDF を「Chrome標準で開く」で開いて、体感で比べてみてください。
- コピー(1ページを画像でクリップボードへ)にかかる時間は、この環境で、長辺 2400 ピクセル(0.1 までの初期値)なら 0.3〜0.4 秒、
  最高画質(0.2 の初期値)なら A4 の文字のページ(600dpi、約 3500×4960 ピクセル)で約 2 秒、600dpi でスキャンした B4 の見開き
  (8598×6070 ピクセル)で約 3.5 秒でした。画像が大きいほど時間がかかります。お急ぎのときは、詳細設定の「画像の画質」を「高画質」にしてください。
- スキャンの整え(0.3)にかかる時間は、この開発環境で、サンプル1(B4・600dpi・9枚・10MB)が、開いて約 2 秒で元のスキャンを表示し、
  約 5〜6 秒で整えた表示に切り替わりました。サンプル2(10枚・26MB)は約 7 秒、サンプル3(8枚・24MB、「冊子を並べ替える」を押してから)は約 5 秒でした。
  調べている間もスクロールなどはできます。お使いのパソコンでは、たいていもっと速くなります。
- 仕様 16章にある「PDFium(WebAssembly 版)の部分採用」は、この計測で製本ビューア(PDF.js)の方が速かったため、見送りました。
  お使いのパソコンで大きな PDF が遅いと感じる場合は、速度ログの記録を教えてください。

### 12.5 フェーズ3の確認

1. **ページ役割が保存され、同じ PDF を開き直すと復元される**

## 13. 既知の制限

- Chrome 128 より古い Chrome では動きません。
- Web ページの中に埋め込まれた PDF(iframe や embed)は切り替えません。タブで開く PDF だけが対象です(仕様どおり)。
- Chrome ウェブストアや `chrome://` のページなど、拡張機能が動けないページでは使えません。
- 一度しか使えない URL は、1回目は開けません(上記 7章)。POST の応答として返る PDF は、Chrome 標準ビューアで表示されます。
- 第3層は「ファイルの URL へのアクセス」の許可が必要です。Chrome の「名前を付けてリンク先を保存」でも製本ビューアが開きます。
- Chrome の PDF 設定が「PDF をダウンロードする」になっている場合の動作は保証しません(初回案内で確認してください)。
- PDF 内の JavaScript(フォームの自動計算など)は実行しません。
- 印刷の画質が「最高画質」のときは Chrome の印刷機能を使うため、Chrome の PDF 設定が「PDF をダウンロードする」のときは使えません(画像にして印刷します)。
  ブラウザのメニューから印刷したときも、画像にして印刷します。
- ファイルとしてのコピーには補助プログラムが必要です(無いときは、ファイルの場所を文字でコピーします)。補助プログラムが無く、
  Chrome の「保存する前に各ファイルの保存場所を確認する」がオンのときは、コピーのたびに(画像としてコピーでは画像ごとに)保存場所を聞かれます。
- 最高画質の画像は大きく(600dpi のスキャンの B4 の見開きで約 5200 万画素)、コピー・保存に数秒かかります。
- Windows・Mac の補助プログラムは、開発環境では実機で動かしていません(12.12)。
- ページの削除で「元に戻す」ができるのは、直前の1回だけです。削除したページの書き込みは、元に戻しても戻りません。
- ページの並べ替え・ほかの PDF のページの挿入はできません(削除だけです)。
- タブの × で閉じるときの確認は Chrome の決まった画面です(「保存しますか?」の独自の画面は、⋮ →「PDFを閉じる」・別の PDF を開くときなどに出ます)。
- パスワード付きの PDF でページを削除して保存すると、フォームの入力内容は保存されません(書き込みとページの削除は保存されます)。
- 5000ページを超える PDF では、全部のページを読み込むまでページを削除できません。
- 電子署名の検証・表示、注釈へのコメントなど、Chrome 標準ビューアの一部の機能はありません。
- 収集した PDF の元データとページ役割は、拡張機能を削除すると消えます(書き出したファイルは残ります)。
  ページ役割は「設定の書き出し」でファイルに残せますが、収集したページは書き出しの対象外です(必要なら PDF で書き出してください)。
- 面付けでは、紙の厚みによる「ずれ」(クリープ)の補正、トンボ、ノド(綴じ側の余白)の調整はしません。
- 面付けした PDF ではリンクが外れます(印刷用のため)。
- スキャンの整え(傾き): 直すのはページ全体の傾き(約 0.2〜8°)です。ページの中で場所によって傾きが違うもの(本のページが波打っている)は
  ページ全体の傾きだけを直し、0.2° 前後のごく小さな傾きは、直ることも直らないこともあります(0.6.0・0.6.2 を参照)。
- スキャンの整え: 余白を除く判断は、画像の明るさから推し量るものです。ページいっぱいの写真・濃い色の表紙などでは、うまく除けないことがあります
  (そのときは「整え方を変える…」で「余白を除く」を外してください)。本の見開きと冊子の紙の見分け、冊子の並べ方は、ページ番号を読んで
  確かめているわけではありません。並びはプレビューで確かめてください。
- スキャンの整え(0.6.5): 分けないページ(写真など)の「余白を除く」も、画像の明るさから紙の範囲を推し量ります。背景と紙の明るさの差が
  小さいもの(白い紙を白い背景の上で撮ったものなど)では、紙の範囲が見つからず、余白を除けないことがあります。除けないときは、元のまま表示します。
  また、紙の端に濃い落ち影が続いているときは、その手前(影の内側)で切り取ることがあります。
- スキャンの整え: 整えた PDF には、元の PDF の目次(しおり)・リンク・フォーム・注釈は入りません。パスワード付きのスキャンを整えると、
  整えた PDF にはパスワードが掛かりません(元に戻すときは、もう一度パスワードを聞かれます)。
- 電子書籍: **KFX は表示も変換もできません**。DRM(コピー防止)のかかった本(Kindle ストア・楽天 Kobo・Adobe DRM など)は開けません(DRM を外す処理は作りません)。
- 電子書籍: Kindle の形式(MOBI・AZW3・KFX)への書き出しはできません。PDF から作る EPUB は画像の EPUB(固定レイアウト)で、
  文字を流し込む(リフローの)EPUB は作れません(PDF には文字の並びの情報が無いため)。
- 電子書籍リーダー: 音声の読み上げ、注釈(マーカー・メモ)、辞書はありません。本の中のスクリプトを使う本(問題集の答え合わせなど)は、その部分が動きません。
  縦書きの本は見開き(2 ページ並び)にできません(画面いっぱいの 1 ページで表示します)。
- 電子書籍リーダーの「PDF に保存」: Chrome の印刷機能を使うので、毎回印刷画面で「PDF に保存」を選ぶ必要があります。
  本のスタイルは章をまたいで 1 つにまとめるため、本によっては画面の表示と少し違う見た目になります。ページ番号は入りません。
- コミック: 見開きの画像の見分けは画像の縦横の比率だけで行います。1 枚の画像に 2 ページ分が入っているかどうかは見ていません。
  見開きの位置合わせの白紙のページは、保存した PDF にも入ります(分けたくないときは、詳細設定で「見開きの画像を分ける」を外してください)。
- CBR: パスワード付きの書庫・分割された書庫(.part1.rar など)は開けません。
- 1 つのファイルが非常に大きいもの(数 GB)は、メモリーが足りず開けないことがあります。
